# Автоматическое наполнение правил

Статус: требование пользователя и план подключения. Реализация рендерера и публичного API — отдельный шаг. Сейчас подготовка текстов не меняет код расширения, настройки или базу.

## Принцип

Авторский текст правил и лора сохраняется в файлах. Списки сущностей и таблицы числовых правил формируются из тех же действующих данных, которые использует расширение.

После изменения уровня выдачи, цены, навыка, перка, расы или заклинания в админке соответствующий блок страницы должен обновляться без ручной правки Markdown и без новой миграции.

JSON из `jsons` служат импортом и экспортом, а не источником действующих правил страницы. Файлы `resources/rules` задают начальную конфигурацию установки. Для публичного отображения читаем актуальные настройки из базы через существующий сервис конфигурации и записи действующих справочников.

## Какие сведения подтягивать

| Блок | Действующий источник |
| --- | --- |
| Стоимость повышения | Настройки развития: диапазоны и цены получения следующего уровня |
| Повышения характеристики | Выборы навыков и владений, автоматические владения, пороги урона и защиты, ресурсов и кругов из настроек развития |
| Навыки характеристики | Справочник навыков, связь с характеристикой, уровни I–III и ссылки на перки |
| Перки | Название, иконка, описание и встроенные эффекты из справочника перков |
| Владения | Название, иконка и описание из справочника владений |
| Расовые особенности | Раса, её бонусы, фиксированные и выбираемые выдачи, связанные перки и заклинания |
| Пути магии | Названия, иконки и описания путей из справочника |
| Заклинания | Карточки из справочника с путём, кругом, описанием и параметрами |
| Предметы и ориентиры оружия | Справочник предметов; точные значения у конкретного предмета, а не у типа оружия |
| Ранги | Порядок, буква и название из справочника рангов |
| Начало игры | Сумма стартовых очков, границы, количество заклинаний, золото и наборы из настроек создания |

Описание навыка не является копией описаний его перков. При добавлении навыка он появляется в списке своей характеристики; уровни и перки показываются по сохранённым связям. При добавлении произвольного перка он появляется в соответствующем общем списке, но не считается навыковым или расовым без такой связи.

## Границы блоков в файлах

Обычный `<div>…</div>` пока служит для ориентирования при редактировании. Для будущей динамической вставки резервируем явный маркер:

```html
<div data-roleplay-block="experience-costs"></div>

<div data-roleplay-block="attribute-development" data-attribute="physiology"></div>

<div data-roleplay-block="skills" data-attribute="physiology"></div>

<div data-roleplay-block="race-features" data-race="poluelf"></div>

<div data-roleplay-block="magic-paths"></div>
```

Первый маркер уже поставлен вместо ручной таблицы стоимости в `../tabs/rules.md`: пользователь указал брать цены из админки. Сейчас он не исполняется и не подгружает данные. При подключении страницы вместо него появится действующая таблица.

Остальные таблицы и полные описания в исходных файлах пока остаются на месте. Заменять их пустыми маркерами до готовности рендерера не нужно. При подключении каждый ручной блок заменяется соответствующей вставкой; одновременно две версии не выводятся.

Маркеры относятся только к заранее разрешённым блокам. Они не выполняют код и не позволяют произвольно читать таблицы базы или загружать внешние сайты. Системные ключи используются для привязки; отображаемое имя берётся из справочника и может меняться.

## Предложенная архитектура

1. Существующие сервисы настроек и справочников читают действующие данные. Формулы и цены повторно не реализуются.
2. Один поставщик публичного содержания собирает безопасный набор данных для страницы. Он объединяет сведения о выдачах, порогах и связанных записях, сохраняя несколько событий на одном уровне.
3. Загрузчик текста распознаёт разрешённые маркеры. Авторские абзацы проходят обработку Markdown/BBCode, а динамические вставки передаются компонентам.
4. Компоненты таблиц и списков показывают эти сведения. Для перков, предметов и заклинаний повторно используются общие карточки, форматирование чисел и словарь иконок.

Название поставщика и адрес API выберем при реализации; новая параллельная база справочников не нужна. Страница получает публичные сведения, без данных персонажей, истории выдач и закрытой базы NPC.

Для доступного игрокам выбора по умолчанию показываются включённые записи. Отдельный режим отображения архивных записей определяется явно; уже полученные способности в профиле это решение не удаляет.

## Обновление и кэш

Данные запрашиваются при открытии страницы. Если потребуется кэш, его актуальность определяется действующей версией справочников и настроек, а не датой сборки JavaScript. Изменения в админке должны обновлять версию и инвалидировать кэш.

Минимальное требование — свежие данные после обновления страницы. Обновление уже открытой страницы без перезагрузки можно добавить позже; оно не должно требовать пересборки или копирования текста.

## Проверки при подключении

- Цена и порог в правилах совпадают с действующим мастером/повышением.
- Новый навык появляется у нужной характеристики вместе с правильными перками.
- Две выдачи на одном уровне не теряются при объединении таблицы.
- На страницу не попадают выключенные варианты выбора и закрытые данные.
- После изменения админки старый кэш не сохраняет прежние значения.

До публикации отдельно согласуем вид таблиц и списков. Подготовка динамических данных не даёт основания сокращать или переписывать окружающий авторский текст.
