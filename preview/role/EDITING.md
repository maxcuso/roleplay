# Как редактировать страницу /role

Страница открывается через локальный сервер: <http://127.0.0.1:4173/role>. Тексты находятся прямо в `index.html`. Для запуска можно открыть `C:\Forum\Flarum\start-role-preview.cmd` и оставить окно сервера работающим.

На Docker-форуме: <http://localhost:8081/role>. Тот же HTML и CSS используются при сборке
расширения: после изменений выполните `pnpm run build` из `packages/roleplay-new/js`,
затем очистите кеш тестового форума. Подробнее: [Перенос на форум](../../docs/29-guide-page.md).

## Где что находится

| Файл | Что менять |
| --- | --- |
| `index.html` | Тексты, порядок блоков, картинки и разметку |
| `style.css` | Размеры, цвета и внешний вид компонентов |
| `content.js` | Подписи главных вкладок, примеры персонажей и иконки характеристик макета |
| `page.js` | Оболочка стенда: переключение темы и автообновление |
| `../../resources/guide/page.js` | Общее поведение вкладок, спойлеров, оглавления, галереи и окна |
| `assets/` | Картинки и шрифты |

Основной текст не собирается из Markdown. Чтобы добавить похожий блок, скопируйте пример соответствующего компонента и измените его содержимое.

## Общие размеры и цвета

В начале `style.css`:

```css
--role-width: 1160px;          /* Вся страница */
--role-document-width: 860px; /* Все блоки документов */
--role-media-width: 240px;    /* Дополнительная колонка шага */
--role-gutter: 36px;          /* Отступ от края экрана */
```

`--role-accent` — цвет текущего раздела. Заметки, рамки и значки наследуют его. Для отдельного блока можно указать `data-accent="ember"`, `water`, `earth`, `air`, `forest`, `gold` или `violet`. Светлая и тёмная палитры находятся рядом в начале CSS.

Ширину картинки можно изменить только для одного шага:

```html
<section class="Step" style="--role-media-width: 280px">
  <!-- Контент и иллюстрация -->
</section>
```

У обычных заголовков и абзацев нет специальных классов. Их оформляют правила внутри `Document` и конкретного компонента. Класс добавляется только там, где у элемента есть отдельная роль.

## Section — раздел документа

```html
<section class="Section">
  <h2>Название раздела</h2>
  <p>Основной текст.</p>
</section>
```

У всех разделов одна ширина. `Section--nested` используется для вложенных разделов, например отдельных рас или поселений.

## Step — контент и дополнительная колонка

Первый дочерний элемент — основной текст, второй — картинка, памятка или другой дополнительный контент.

```html
<section class="Section Step">
  <div>
    <h2>
      <span class="Badge" aria-hidden="true">1</span>
      Название шага
    </h2>
    <p>Основной текст.</p>
  </div>
  <figure class="Figure Figure--framed Figure--placeholder">
    <i class="Icon fas fa-image" aria-hidden="true"></i>
    <figcaption>Место для изображения</figcaption>
  </figure>
</section>
```

Модификаторы:

- `Step--reverse`: дополнительная колонка слева. HTML остаётся в том же порядке.
- `Step--balanced`: две примерно равные колонки для текста и текстовой памятки.
- `Step--wide-copy`: широкая текстовая колонка занимает 3/4 строки; на телефоне — всю ширину. Так оформлены история и вступление в организацию.
- `Step--organization`: шапка организации — название капсом в цвет города, описание, тип и лидер слева; герб справа. На телефоне герб располагается над текстом.
- `Step--wide-aside`: примерно треть ширины основному тексту и две трети дополнительному контенту, например перкам навыка. Сочетание `Step Step--wide-aside Step--reverse` помещает перки слева, навык справа.
- `Step--panel`: цветная подложка и компактная иллюстрация, как у рас.

Внутри другого раздела достаточно `Step`, без `Section`. На телефоне основной текст всегда сверху, дополнительный контент — ниже.

Для навыков сохраняйте одинаковый порядок HTML: сначала `div.Skill` с заголовком и описанием, затем `div.Grid.Grid--stack` с перками. Чередование задаётся классом `Step--reverse` у каждого второго навыка; на телефоне навык всегда предшествует своим перкам.

Вместо числа в `Badge` можно поставить иконку:

```html
<span class="Badge" aria-hidden="true">
  <i class="Icon fas fa-scroll"></i>
</span>
```

## Note — заметка

```html
<aside class="Note">
  <h3><i class="Icon fas fa-book-open" aria-hidden="true"></i>Важно</h3>
  <p>Пояснение или правило.</p>
</aside>
```

Заголовок и иконка необязательны. Фон берётся из цвета раздела. Варианты: `Note--warning`, `Note--success`, `Note--compact` и `Note--medium`.
`Note--compact` — единый стиль для «Шаблона» и компактных заметок с таблицами: отступы 15 px, скругление 14 px,
заголовок 18 px акцентного цвета, текст 11 px с межстрочным интервалом 1,1, цветная смещённая тень и наклон 0,5°.
`Note--medium` сохраняет это оформление, но использует текст 13 px и межстрочный интервал 1,4.
Применяйте его отдельно: `class="Note Note--medium"`.
Отдельный `style="rotate: 1deg"` задаёт собственный наклон вместо стандартного.
У таблиц межстрочный интервал 1,2 и отступы ячеек 8 × 10 px.

`Note--partial` задаёт заметке 3/4 ширины раздела и выравнивает её по центру: `class="Note Note--partial"`.
На телефоне такие заметки занимают всю ширину. Модификаторы можно сочетать с `Note--success` и другими цветами заметки.

## Banner — заголовок с выступающей картинкой

```html
<div class="Banner">
  <h2>Валюта</h2>
  <p>Краткая подпись.</p>
  <img class="Banner-art" src="/role/assets/example.png" alt="">
</div>
```

Картинку можно заменить встроенным SVG с тем же классом. В текущих плашках SVG уже вставлены непосредственно в HTML.

Для спойлера используйте тот же баннер как `summary` внутри `details`:

```html
<details class="Banner--spoiler" open>
  <summary class="Banner">
    <h2>Валюта</h2>
    <p>Краткая подпись.</p>
    <!-- Здесь можно оставить Banner-art. -->
  </summary>
  <dl class="Facts">
    <!-- Всё, что должно скрываться вместе с этим баннером. -->
  </dl>
</details>
```

Атрибут `open` означает «открыт при загрузке». Уберите его, чтобы блок изначально был закрыт.
Весь баннер переключает состояние; язычок со стрелкой оформляется в CSS и не требует разметки.
Соседние спойлеры работают независимо. При переходе по якорю внутри блока он раскрывается автоматически.

При наведении язычок выдвигается ещё на 4 px. При переключении он сначала втягивается,
а затем появляется с другой стороны. Скорость одного движения задаёт `--banner-tab-duration`
в CSS (по умолчанию 160 ms). При системной настройке уменьшенной анимации переключение мгновенное.

## Facts — строка сведений

Это список определений: `dt` — название, `dd` — значение. У каждого сведения одна обёртка `div`.

```html
<dl class="Facts Facts--cards">
  <div>
    <dt>Владение оружием</dt>
    <dd>Одноручное оружие, щиты</dd>
  </div>
  <div>
    <dt>Навыки</dt>
    <dd>Рукопашный бой, внимательность</dd>
  </div>
</dl>
```

По умолчанию четыре колонки. `Facts--three` задаёт три, `Facts--cards` — две на отдельных подложках. `Facts--compact` ограничивает ширину короткой строки, как в «О ролевой». `Facts--wide-third` расширяет третью графу, как у рас, сохраняя обычное оформление `Facts`. Произвольное число колонок можно указать через `style="--columns: 3"`.

Для трёх пунктов с более широкой серединой используйте `Facts Facts--three Facts--wide-center`: пропорции колонок — 1 / 1,6 / 1. На телефоне они располагаются одним столбцом. Так оформлены первый ряд параметров заклинаний и типы заклинаний. Второй ряд параметров использует обычный `Facts` с четырьмя колонками.

## Figure — иллюстрация

Цветные иконки баннеров лежат в `assets/banner-icons/` и подключаются обычным `img.Banner-art`. Размер, положение, наклон и тень задаёт общий `.Banner-art`, как у прежних SVG. Исходные PNG и SVG сохранены без изменений. При добавлении новой иконки внесите её имя в `bannerIconNames` в `preview/server.cjs` и перезапустите сервер.

```html
<figure class="Figure Figure--framed">
  <img src="/role/assets/locations.jpg" alt="Путешественники перед городом">
</figure>
```

- `Figure--placeholder`: заглушка с иконкой и подписью.
- `Figure--framed`: рамка, небольшой наклон и тень.
- `Figure--portrait`: портретные пропорции без обрезки.
- `Figure--cutout`: изображение без подложки и рамки.

При замене заглушки настоящей картинкой уберите `Figure--placeholder` и вставьте `img` вместо её содержимого. Внешний `figure` сохраняется. Если картинка новая, добавьте её в список файлов в `preview/server.cjs` и перезапустите сервер.

## Grid — сетка повторяющихся блоков

```html
<div class="Grid">
  <aside class="Note Note--compact">
    <h3>Первый блок</h3>
    <p>Описание.</p>
  </aside>
  <aside class="Note Note--compact">
    <h3>Второй блок</h3>
    <p>Описание.</p>
  </aside>
</div>
```

По умолчанию две колонки. `Grid--stack` — одна колонка, `Grid--symbols` — сетка символов 2×2. `Grid--fill-last` растягивает последний нечётный элемент на весь ряд. Число колонок меняется переменной `--columns`.

`Grid--staggered` располагает заметки `Note` по одной в ряд, на 3/4 ширины: нечётные слева, чётные справа.
На телефоне заметки занимают всю ширину. Так оформлены божества во вкладке «Мир».

## City — город

`City` объединяет заголовок с кружком-иконкой, герб, панораму, четыре колонки `Facts` и основной текст.
Гербы соседних городов автоматически чередуются слева и справа. `data-accent` задаёт цвет города.
Заголовок-плашка и герб перекрывают верхний край панорамы; отступ заголовка от края задаёт `padding-inline` у `City-header`.

```html
<article class="City" data-accent="forest" data-settlement="city-key">
  <header class="City-header">
    <h3><span class="Badge" aria-hidden="true"><i class="Icon fas fa-compass"></i></span><span>НАЗВАНИЕ</span></h3>
    <figure class="City-crest"><img src="/role/assets/crest.png" alt="Герб города"></figure>
  </header>
  <figure class="Figure City-image"><img src="/role/assets/city.jpg" alt="Панорама города"></figure>
  <dl class="Facts"><!-- Правитель, население, преобладающие расы, отношения. --></dl>
  <div class="City-copy"><p>Основной текст города.</p></div>
</article>
```

Гербы городов подключены из `assets/city-crests/`. Актуальный список находится в `content/flags/manifest.json`: Квестпост — `questpost-v2.png`, Грим — `grim-v5.png`, оба без корон.
Панорамы без готовых изображений заменены заглушками. Для настоящей панорамы замените содержимое `City-image`
картинкой и уберите `Figure--placeholder`. Значения сводки подготовлены для будущего подключения справочника.
Прочерки означают, что данных пока нет. На телефоне `Facts` располагается в две колонки.

## Tabs — вкладки

У всех наборов вкладок один обработчик. Кнопка ссылается на панель через `aria-controls`, панель — на кнопку через `aria-labelledby`. Эти идентификаторы должны быть уникальными.

```html
<div class="Tabs" data-tabs="example" role="tablist" aria-label="Пример">
  <button id="tab-one" type="button" role="tab"
          aria-controls="panel-one" aria-selected="true" tabindex="0">Первая</button>
  <button id="tab-two" type="button" role="tab"
          aria-controls="panel-two" aria-selected="false" tabindex="-1">Вторая</button>
</div>
<section class="TabPanel" id="panel-one" role="tabpanel" aria-labelledby="tab-one">
  <p>Первая панель.</p>
</section>
<section class="TabPanel" id="panel-two" role="tabpanel" aria-labelledby="tab-two" hidden>
  <p>Вторая панель.</p>
</section>
```

`Tabs--icons` — круглые кнопки с иконками: задавайте им понятные `aria-label` и `title`. Так переключаются характеристики и группы организаций. `Tabs--sticky` — закреплённая главная навигация. `TabPanel--reading` задаёт отступ после подробного описания характеристики.

Организации находятся в конце раздела «Мир», прямо в `index.html`. Семь вкладок с `data-tabs="organizations"` показывают шесть городов и группу «Общие»; организации внутри вкладки идут подряд. Каждая отмечена `data-organization`. Шапка — `Step--organization`; содержательные шаги пронумерованы заново внутри каждой организации. Устройство — `Step--reverse`, слева `Note--compact` с рангами, званиями, ветвями или статусами. Если отдельного перечня нет, используется `Step--wide-copy` без пустой памятки. Поля местоположения, штаб-квартиры и сферы влияния не выводятся. Особые разделы — `Note--medium`. Если истории или условий вступления нет в исходном тексте, пустой шаг не добавляется.

Герб использует `Figure Figure--crest`, без обрезки. Все 19 организаций имеют изображения в `assets/organization-crests/`. Итоговые оригиналы лежат в `content/flags/src/`; после их изменения запустите `node packages/roleplay-new/content/flags/sync-heraldry.cjs` из корня проекта, чтобы обновить копии и список маршрутов. При изменении списка файлов перезапустите локальный preview-сервер.

Левая часть «Устройства» показывает структуру самой организации: таблицу рангов или званий, `Facts` с должностями, ветвями либо статусами. Это относится и к перечням, которые в источнике написаны обычными абзацами. Не заменяйте их общей памяткой «Сведения». Если отдельных перечней несколько, используйте `Grid Grid--stack` с несколькими `Note--compact`. Называйте их по смыслу: например, «Круги посвящения» у Эр’Та и «Пути служения» у Пантеона; последние не являются последовательными рангами.

Текст уже перенесён из `content/world.md`: при загрузке страницы этот файл не читается. Для новой вкладки свяжите кнопку и панель через `aria-controls` / `id`, как в примере выше; общий обработчик в `page.js` работает и с мышью, и с клавиатурой.

Оглавление `Contents` использует обычные ссылки, а не вкладки. В правилах восемь тем, в мире четыре, в персонаже шесть. Ссылки ведут к началу соответствующей темы: например, «Квесты и награды» — к баннеру развития, «Развитие в профиле» — к шагу повышения характеристик. Оставляйте `id` только у заголовков, на которые действительно ведут ссылки.

Начиная с ширины экрана 1100 px оглавление находится в отдельной левой колонке и удерживается через `position: sticky; top: 90px` в пределах текущей вкладки. Документ сохраняет ширину до 860 px. На более узких экранах ссылки располагаются компактными кнопками над текстом. Подсветка текущей темы обновляется при прокрутке; адрес меняется только при переходе по ссылке. `restoreTabs` раскрывает нужные вкладки и спойлеры, в том числе при прямом открытии якоря.

### Вкладка «Персонаж»

В `panel-application` два открытых по умолчанию баннера-спойлера: «Создание персонажа» и «Развитие персонажа». Под каждым — `Facts--three`, затем чередующиеся `Section Step` / `Section Step Step--reverse`. Нумерация начинается заново в каждом разделе. Объяснение всегда первое в HTML, скриншот — второй, поэтому на телефоне порядок одинаковый.

В создании десять шагов: «С чего начать», «Мастер создания» (первая страница), «Характеристики», «Навыки и владения», «Перки», «Заклинания», «Снаряжение», «Итог и создание темы», «Художественная анкета», «Проверка и принятие». Каждый этап мастера имеет отдельный шаг и скриншот; не объединяйте несколько его экранов в один блок.

В развитии восемь шагов: выбор задания, прохождение квеста, награды и опыт, повышение характеристик, навыки и владения, перки и заклинания, экипировка, эффекты и история. Сначала объясняем получение наград в игре, затем действия с ними в профиле. В конце развития находятся заметки об опыте ролевика и смерти персонажа. Заглушки скриншотов заменяются изображениями обычным способом через `Figure`.

Кнопка создания в первом шаге использует тот же `data-action="create-character"`, что и кнопка главного баннера. Обработчик в `page.js` подключается ко всем таким кнопкам.

## Table и Timeline

Обычная таблица помещается в прокручиваемую обёртку:

```html
<div class="Table">
  <table>
    <thead><tr><th>Уровень</th><th>Значение</th></tr></thead>
    <tbody><tr><td>1</td><td>10</td></tr></tbody>
  </table>
</div>
```

Шкала развития:

```html
<ol class="Timeline">
  <li>
    <span>1</span>
    <div>Первое улучшение.</div>
  </li>
  <li>
    <span>2</span>
    <div>Следующее улучшение.</div>
  </li>
</ol>
```

Отдельные классы для номера уровня и его описания не нужны.

## Иконки, данные и обработчики

Интерфейсная иконка из реестра:

```html
<i data-icon="resources.gold" class="Icon" aria-hidden="true"></i>
```

Иконка характеристики из её записи:

```html
<i data-attribute-icon="physiology" class="Icon" aria-hidden="true"></i>
```

В макете записи характеристик находятся в `content.js`. На форуме `paintAttributeIcons` получает `catalog.definitions.attributes` из базы. Ключи: `physiology`, `agility`, `magic`, `charisma`.

У всех навыков в бейдже используется `data-attribute-icon` своей характеристики. Тот же источник задаёт иконки вкладок и сетки 2×2. Внутри каждой панели сначала идёт `Step Step--panel` с описанием характеристики, затем заметки о ресурсах при наличии, `Facts Facts--cards` со списками владений и навыков, шкала развития и чередующиеся блоки навыков. Названия в `Facts` выделены через существующий `paper-highlight`.

`data-attribute-skills="physiology"` — место всех навыков характеристики, без заданного
количества блоков в HTML. На форуме они создаются из включённых записей справочника:
название, описание, характеристика и перки берутся из базы. Порядок задаётся `sort_order`,
при равенстве — ID. Стороны Step чередуются с первого навыка каждой характеристики;
на телефоне описание идёт перед перками. Краткий перечень в Facts использует
`data-attribute-skill-list="physiology"`. Остальные ключи: `agility`, `magic`, `charisma`.

`data-roleplay-block` отмечает места данных, например стоимость повышения и три примера перков.
На Docker-форуме примеры перков, созданные вместе с навыками слоты `data-skill-perks="slug"`
и расовые `data-race-perks="slug"` заполняются из базы общим `PerkCard` мастера и профиля.
Используйте постоянный slug справочника, а не название.

`data-races` — место всех включённых рас. Их количество, порядок, название, цитата,
основной текст, портрет, справочные сведения и бонусы задаются справочником.
Разметка в `js/src/forum/guide/GuideRaces.tsx` использует прежние Step--race, Facts--wide-third,
Grid и PerkCard; оформление рамки и выступа картинки по-прежнему находится в style.css.
На стенде 4173 без базы вместо рас и навыков остаются поясняющие заглушки.
`Grid` располагает карточки и не задаёт их внутреннее оформление. Номер уровня навыка оформляется
через `Badge--level` сбоку от карточки в `Step--perk`.

Шкалы четырёх характеристик — слоты `data-attribute-development="physiology"`,
`agility`, `magic`, `charisma`. Их строки на форуме создаются из базы настроек развития,
включая формулировки; редактируются в админке «Развитие», в окне соответствующего правила.
Степень урона подставляется через `{damage}` и оформляется как `span.paper-highlight`.
Вступительное описание самой характеристики по-прежнему редактируется в этом HTML.
Отдельный стенд на 4173 без базы вместо шкал показывает поясняющие заглушки.

Кнопки используют `data-action`, служебные поля — `data-part`. Для них не надо создавать `id`. Идентификаторы остаются у якорей, подписей и панелей вкладок.

Предлоги, короткие союзы и частицы связываются со следующим словом обычным
неразрывным пробелом U+00A0 (старые узкие пробелы тоже заменяются на него)
при показе страницы. В HTML и базе можно продолжать писать обычные пробелы.
Обработка сохраняет выделения и ссылки, пропускает код и поля ввода. Если для
отдельного фрагмента это не нужно, добавьте контейнеру `data-no-typography`.

`Diagram` — особая схема анкеты с выносками. Её и галерею персонажей не нужно переделывать в `Step`: у них собственная структура. Настоящие анкеты в галерее настраиваются в массиве `characters` файла `content.js`.
