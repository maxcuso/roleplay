# Roleplay для Flarum

Расширение для ролевых форумов на Flarum 2.x. Пакет: `maxcuso/flarum-roleplay`.

## Возможности

- Создание персонажа через мастер с сохранением черновика.
- Анкета выбранного персонажа в профиле пользователя.
- Раздельная проверка технической и литературной частей анкеты.
- Навыки, владения, перки, заклинания, предметы и экипировка.
- Числовые эффекты и расчёт параметров персонажа.
- Развитие за опыт, выдача и изъятие ресурсов и сущностей модератором.
- Ручное назначение рангов, история персонажа и статистика ролевика.
- Справочники и настройки в админке, импорт и экспорт JSON.
- Страница `/role` с правилами, миром и руководством по персонажу.
- События и квесты: карточки в сообщениях, запись участников, выбор персонажа и запуск тем по расписанию.
- Личная модераторская: свои эпизоды и рабочие справочники с отдельными правами доступа.

Обучение заклинаниям из литературы в инвентаре уже работает. Крафт, рецепты, чертежи и чары остаются в разработке.

## Требования

- PHP 8.3 или выше в пределах ограничения `^8.3`.
- Flarum в пределах ограничения `^2.0.0-rc.8`.
- Расширения `flarum/tags`, `flarum/lock` и `flarum/mentions` в пределах ограничения `^2.0.0-rc.8`.
- Проверено на Flarum 2.0.2 и PHP 8.5.12; SVG поддерживает `svg-sanitize` 0.22 и 1.1.

Точные зависимости указаны в [composer.json](composer.json).

## Установка и настройка

Установка выполняется из папки форума:

```text
composer require maxcuso/flarum-roleplay
php flarum cache:clear
```

Для предварительных версий Composer может потребовать указать конкретную версию.

После установки включи расширение в админке, настрой права, заполни справочники и стартовые наборы. В настройках анкет укажи тег для литературных тем. Затем можно включить создание персонажей.

Новая и прежняя локальная версии используют одинаковые имя пакета и таблицы. Их нельзя устанавливать одновременно. Чистая установка использует одну базовую миграцию без тестовых персонажей. История единственной локальной установки приведена к ней отдельно, без изменения данных. [Объединение миграций и проверки](docs/40-schema-consolidation.md), [перенос справочников](docs/17-transition.md).

## Разработка и публикация

Из папки `js`:

```text
npm ci
npm run types:sync -- /forum/vendor/flarum/core/js/dist-typings
npm run typecheck
npm run build
```

В `types:sync` укажите путь к типам установленного Flarum. Готовые файлы `js/dist` входят в релиз. Локальные зависимости, сгенерированные типы `.flarum-typings`, `tests/.runtime` и `icons.local.json` исключены из публикации. Для зависимостей используется один lock-файл — `js/package-lock.json`.

Перед выпуском отключите локальные замены иконок и пересоберите интерфейс: исключение `icons.local.json` из архива само по себе не убирает замены из готового JavaScript. Отдельная копия проекта для этого не нужна. [Подготовка GitHub, Packagist и Floxum](docs/27-publishing.md).

## Как работаем

Перед каждой подсистемой:
1. Описываем пользовательский сценарий и ожидаемый результат.
2. Даём план шага, архитектуру классов/компонентов и связи между ними.
3. Разбираем данные, правила, права доступа и вопросы, влияющие на реализацию.
4. Реализуем согласованный объём и проверяем его.
5. Обновляем документацию: что сделано, где менять поведение, что остаётся следующим шагом.

Код пишем с понятными именами и комментариями на русском. В комментариях объясняем назначение участка, причины ограничений и место настройки. Избегаем сжатых строк с несколькими действиями.

Существующая папка ../roleplay служит источником согласованных сценариев и референсом. Новый проект не копирует её устаревшие поля и обходные решения автоматически.
