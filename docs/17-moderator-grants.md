# Выдачи из профиля

Окно открывается кнопкой «Выдать» у активного персонажа. Владельцы и посетители не получают права выдачи. Модератор определяется существующим правом `roleplay.moderate`.

## Вид окна

- Первой открывается вкладка «Ресурсы»: опыт и золото меняются одной командой с общей причиной.
- Нулевое количество пропускается. Переключатель определяет начисление или списание; отрицательные числа вводить не нужно.
- Перки, заклинания и предметы выбираются в списке с поиском. Прокручивается только список, а не поиск или кнопка сохранения.
- При изъятии показываются принадлежащие персонажу сущности. Для предмета выбирается конкретная стопка и количество.
- Источник перка указывается при выдаче. Зависимые поля берутся из определения источника.
- «Ранг» пока показывает «В разработке».

## Общие редакторы

Кнопка «Создать» открывает общий `CatalogEditModal` поверх окна выдачи через поддерживаемый Flarum 2 стек окон. Отмена закрывает только редактор. После сохранения обновляются версия анкеты и список выдачи; созданная запись выбирается автоматически. Причина, суммы и параметры выдачи остаются в нижнем окне. Создание записи само по себе не выдаёт её персонажу.

Общие файлы:

- `js/src/common/editors/` — поля перка, заклинания и предмета.
- `js/src/common/catalog/components/` — окно, поля, предпросмотр, изображения и эффекты.
- `js/src/common/catalog/definitions/` — общие описания этих сущностей.
- `resources/catalog-editor.css` — оформление общих редакторов, подключено к админке и форуму.
- `resources/management.css` — геометрия окна выдачи, высота списка и переключатели.
- `resources/presentation/icons.json` — все служебные значки, включая `management.*`.

Редакторы не зависят от `flarum/admin/app`. Админка использует свой `CatalogApi`; создание из профиля — ограниченный `ManagementCatalogApi`.

## Сервер

`GET /roleplay/management/catalogs/{catalog}` возвращает версию и только ссылки, нужные редактору. `POST` создаёт запись теми же нормализаторами, что админка. Допустимы только `perks`, `spells`, `items`. Изменение существующих записей, статусы и удаление остаются административными. Загрузка изображения использует прежнюю очистку/проверку файлов.

Команда `reward` передаёт целые изменения `experience` и `gold`. Они должны иметь одинаковый знак либо быть нулевыми; оба нуля запрещены. `CharacterOperation` обеспечивает одну транзакцию, версии, UUID и историю. Ошибка второго баланса откатывает первый; повтор UUID не начисляет награду второй раз. Полученный опыт увеличивает активный и накопленный; списание уменьшает только активный.

Старый серверный контракт `balance` оставлен совместимым, но новое окно его не использует. Миграций для этих изменений не требуется.
