# Создание персонажа: серверная часть

Работа выполнена только в roleplay-new. Пакет не установлен; старые персонажи, пользователи и таблицы форума не менялись. Интерфейс мастера по новым макетам реализован следующим этапом, см. документ 13.

## Что перенесено

Из прежних AttributePreview, ProgressionPreview, PerkPreview, SpellPreview, LoadoutPreview и CreateCharacter сохранены распределение значений, проверка расовых выборов, последовательный план обучения, группы вещей, защита версий и атомарное создание.

Устаревшая таблица универсальных roleplay_rules, несколько источников одного перка, повторные копии источников/иконок и старые маркеры starting не перенесены. Новое создание использует уже подготовленные каталоги, DevelopmentRules, SkillEligibility и ProficiencyEligibility.

## Согласованные стартовые правила

- Свободное распределение 7 очков между четырьмя характеристиками: каждая от 1 до 3 до расовых прибавок. Допустимы 3 / 2 / 1 / 1 и 2 / 2 / 2 / 1 в любом порядке. Настройка attribute_distribution задаёт сумму очков и границы значений; точная комбинация не обязательна.
- Сохранённый уровень = распределённое значение + расовая прибавка; диапазон 1–25.
- При Магии от 3 обычный стартовый выбор составляет два разных заклинания I круга.
- Фиксированные и выбранные расовые заклинания выдаются сверх обычных. Оба способа обходят требования Магии и круга, но выбор ограничен настроенным расовым списком/путями.
- Выключение заклинания или пути запрещает новое стартовое получение.
- Навык выбирается последовательностью ID: повтор ID означает ещё одно повышение, не произвольное присвоение III уровня.
- Неиспользованные права навыков/владений можно оставить на будущее. Они привязаны к характеристике и порогу.
- При достигнутой Магии 5 автоматическое владение выдаётся без расхода выбора.
- Перки навыковых уровней не заменяют предыдущие. Совпадающий с расовым перк не дублируется; расовая выдача идёт первой и сохраняет свой источник.
- Стартовая выдача перка имеет обычную редкость. rarity_override хранится у выдачи; общий каталог не переписывается.
- Стартовые вещи складываются по ID и разбиваются по max_stack. Автоматически не экипируются.
- Опыт и золото задаёт сервер, не игрок. experience_active и experience_total первоначально равны starting_experience.

## Согласованные стартовые вещи и золото

| Группа | Ключ настройки | Получение | Варианты |
| --- | --- | --- | --- |
| Основное оружие | primary-weapon | Обязательный выбор одного предмета: min = 1, max = 1 | Меч, двуручный меч, лук, магический посох |
| Дополнительное снаряжение | secondary-gear | Обязательный выбор одного предмета: min = 1, max = 1 | Метательный нож, щит |
| Сменная одежда | starting-clothing | Автоматическая группа с единственным вариантом | Комплект сменной одежды |

Каждый вариант выдаёт один экземпляр предмета. Все вещи поступают в инвентарь и автоматически не экипируются. Начальный баланс — 10 золота и 0 активного/накопленного опыта.

Получение оружия не требует владения: при выборе набора доступны все его включённые варианты. Требование владения применяется отдельно при расчёте атаки экипированным оружием в CharacterAttackBuilder. Не переносить эту проверку в LoadoutCreationPlan или фильтрацию вариантов мастера.

Числовое начальное золото задано в resources/rules/creation.php и может быть изменено через серверные настройки. Состав групп и количество предметов задаются в configuration.loadout по ID из нового каталога; имена в таблице выше описывают игровой состав, а не служат для поиска записей в коде.

До заполнения каталогов и привязки конкретных ID создание остаётся выключенным, loadout пуст. Это состояние подготовки расширения; оно не означает, что игроку разрешено пропустить обязательные группы. При настройке нужно добавить обе ручные группы с min = max = 1 и автоматическую группу одежды. Интерфейс администрирования стартовых наборов будет отдельным этапом.

## Черновик

Payload содержит first_name, last_name, age, race_id, base_attributes, racial_attributes, skills, proficiencies, perk_ids, spell_ids, racial_spell_ids и loadout.

base_attributes — объект по системным ключам четырёх характеристик. racial_attributes — список таких ключей. Остальные выборы способностей — списки числовых ID; повтор разрешён только в skills для последовательного повышения. loadout — объект: ключ группы → список ключей вариантов.

Пустые имена, null возраста/расы и неполные выборы сохраняются. При создании все обязательные проверки должны пройти. Поля gold, bonuses, sources, approved и присланные планы не принимаются.

Чтение возвращает личный draft, доступный catalog и preview. Новая форма имеет draft.id = 0 и revision = 0. Сохранение повышает revision. Устаревшая вкладка получает 409 и не затирает новый черновик.

catalog_revision относится к данным админки. rules_hash учитывает также настройки и файлы development.php/stats.php: изменение файла не требует миграции, но требует повторного подтверждения старого черновика.

## API

Все личные операции требуют зарегистрированного пользователя и прав viewForum, roleplay.view, roleplay.create. Настройки доступны только администратору.

| Запрос | Назначение |
| --- | --- |
| GET /api/roleplay/creation/draft | Черновик, определения и предпросмотр |
| PUT /api/roleplay/creation/draft | Сохранение частичного черновика |
| POST /api/roleplay/creation | Окончательное создание |
| GET /api/roleplay/admin/creation | Настройки и общая версия |
| PUT /api/roleplay/admin/creation | Административное сохранение настроек |

PUT черновика: revision, catalog_revision, rules_hash, step, payload.

POST создания: operation_key (UUID v4), draft_id, draft_revision, catalog_revision, rules_hash. Ответ: character_id. Ключ повторного запроса следует сохранять до получения результата; повторять с тем же ключом и теми же полями.

PUT настроек: revision, configuration. Настройки содержат enabled, max_characters, attribute_distribution, starting_spell_count, starting_gold, starting_experience, perk_sources и loadout. Конкретные источники race/skill задаются ID из раздела источников; подбор по названиям не выполняется.

Пример одной группы loadout, с условным ID предмета:

~~~json
{
  "key": "primary",
  "name": "Основное оружие",
  "automatic": false,
  "min": 1,
  "max": 1,
  "options": [
    {"key": "sword", "name": "Меч", "items": [{"item_id": 123, "quantity": 1}]}
  ]
}
~~~

Для автоматической группы требуется ровно один вариант и min = max = 1. Ссылки проверяются при настройке; использованные предметы/источники защищены от удаления. Названия и количества не берутся из запроса игрока.

Форма источников и стартовых наборов в админке пока не добавлена. Для тега и литературного шаблона подключена отдельная форма, см. документ 15. Не вызывайте новые маршруты на старой установленной версии.

## Схема и сохранение

В единственную ещё не установленную базовую миграцию добавлены семь технических таблиц:

- roleplay_creation_config — серверная конфигурация;
- roleplay_actor_states — строка блокировки аккаунта;
- roleplay_creation_drafts — личный черновик;
- roleplay_operations — ключ запроса, контрольная сумма и результат;
- roleplay_character_choices — права порогов и их расход;
- roleplay_character_balances — отдельные значения ресурсов по resource_key;
- roleplay_character_events — история первоначального создания.

У characters добавлены age и creation_catalog_revision; у выдачи перка — nullable rarity_override. Снимок персонажа теперь читает balances, choices и редкость выдачи. Пустые балансы допустимы у прежних тестовых состояний; отсутствующие значения не подменяются начислениями.

Порядок блокировок: справочники → аккаунт → черновик/персонаж. Пользовательская строка в users не изменяется. Лимит учитывает creating и active; одновременно незавершённый созданный персонаж допускается один.

В одной транзакции сохраняются персонаж со статусом creating, характеристики, навыки, владения, перки с источниками, заклинания, вещи, балансы, права выбора, операция и событие. Одобрение литературной части не выдаётся. Тема с литературным шаблоном создаётся автоматически: техническая часть получает review, литературная — draft («В работе») до отправки игроком. После успеха черновик удаляется. Подробности — в документе 15.

Повтор успешного запроса возвращает первоначальный character_id даже после изменения правил или выключения создания. Другой запрос с тем же ключом получает конфликт. Ошибка на любом этапе откатывает все выдачи и сохраняет черновик.

## Проверки и следующие части

creation-scenarios.php выполняется через check-base-catalogs.php только во временной схеме с отдельным префиксом. Проверяются частичный черновик, две вкладки, чужой черновик, запреты гостю, неверное распределение и выборы, последовательные уровни навыка, автоматическое владение, оба расовых обхода Магии, стопки, обычная редкость выдачи, остатки выбора, смена правил, повтор запроса и полный откат при ошибке SQL.

Рабочие пользователи не создаются. Второй актор в проверке — объект в памяти. Тестовый триггер ошибки ставится только на временную таблицу и удаляется.

Прежние проверки эффектов, атак, правил обучения, состояния и интеграции сохранены. Мастер, профиль и модераторская проверка подключены следующими реализованными этапами. Далее отдельно согласуются операции прокачки и выдачи/списания балансов.
