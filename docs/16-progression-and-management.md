# Развитие, выдачи и стартовые настройки

## Правила развития

Стоимость получения следующего уровня хранится в resources/rules/experience.php.
Миграция при изменении цены не нужна.

| Получаемый уровень | Активный опыт |
| --- | --- |
| 2–5 | 3 |
| 6–10 | 10 |
| 11–15 | 25 |
| 16–25 | 100 |

Покупка увеличивает приобретённую характеристику на 1 и уменьшает активный опыт. Накопленный опыт сохраняется.
Максимум приобретённой характеристики — 25. Итоговое значение с эффектами может быть больше.
Последний уровень не открывает обычных выборов навыков/владений.

Пороги выбора находятся в resources/rules/development.php. На пересечённом пороге создаётся одна запись права выбора.
Навык повышается последовательно I → II → III, требует приобретённой характеристики 7 для II и 15 для III.
Каждое обучение тратит один выбор своей характеристики. Новый навыковый перк добавляется к прежним.
Если этот перк уже есть, второй экземпляр и второй источник не создаются.
Обычная редкость относится только к стартовой выдаче; последующее обучение использует редкость определения перка.

Владение либо изучено, либо нет. Автоматическое магическое владение выдаётся на Магии 5, без расхода выбора.
Эффект предмета не открывает порогов, новых кругов и прав обучения.

Изучение книг и похожих предметов отложено за пределы MVP. Книга по согласованному будущему сценарию остаётся у персонажа.
Повышение Магии само по себе не выдаёт новых заклинаний.

## Действия модератора

Выдачи доступны администраторам и пользователям с roleplay.moderate, только через профиль активного персонажа.
Обязательна причина. Можно выдать/изъять перк, заклинание, конкретную стопку предметов, золото и активный опыт.
Во вкладке «Ранг» модератор назначает или снимает ранг из общего справочника I–X;
действие также требует причины и сохраняется в истории. Подробности — [Ранги](21-ranks.md).
У перка выбирается источник выдачи. Название расы/навыка получает сервер из каталога.
У квеста/события название вводит модератор. Определение перка не содержит общей привязки источника.

Новая выдача запрещена для выключенной сущности. Выключенный путь также запрещает выдачу его заклинаний.
Уже полученная выключенная сущность сохраняется и может быть изъята.
Выдача заклинания модератором — явное назначение; обычное обучение игрока и проверка книги ещё не реализованы.
Круг не проверяется при такой выдаче, как и у согласованных расовых исключений.
Предметы выдаются в стопках не больше max_stack, без автоматической экипировки.
При изъятии выбирается ID экземпляра/стопки; экземпляры других персонажей недоступны.

Положительное получение опыта увеличивает оба баланса. Изъятие/расход уменьшает только активный.
Отрицательного баланса быть не может. Одна команда изымает/выдаёт максимум 1000 предметов.
История последних 50 действий видна владельцу и персоналу, посетителю не возвращается.

## API

POST /roleplay/characters/ID/progression: kind=attribute/skill/proficiency, target_id, rules_hash.
GET /roleplay/characters/ID/management: доступные модератору варианты выдачи.
POST /roleplay/characters/ID/management: action, data, comment.
GET/PUT /roleplay/admin/creation: конфигурация старта и селекторы источников/вещей.

Все команды персонажа требуют operation_key, revision, catalog_revision.
rules_hash защищает подтверждение развития, когда изменили файловые правила без SQL-миграции.
Ошибки откатывают опыт и все выдачи. Точный повтор после потери ответа не выполняет действие второй раз.

## Стартовые настройки

Админка содержит отдельный раздел «Создание персонажей»: включение создания, лимит персонажей,
стартовые ресурсы, число обычных заклинаний, источники расовых/навыковых перков, группы и варианты снаряжения.
Автоматическая группа должна иметь один вариант, минимум=максимум=1.
Обычная группа задаёт минимальное/максимальное количество выбранных вариантов.
Ключи групп/вариантов создаёт редактор; в пользовательском интерфейсе они не показываются.

Настройки темы редактируются отдельно, но сохраняют ту же общую версию.
Изменение одного раздела не перезаписывает другой незаметно: старая версия вызывает конфликт.
