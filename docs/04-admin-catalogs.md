# Админка: все разделы

В новой папке подключены таблицы и редакторы рас, путей магии, типов предметов, источников перков, заклинаний, предметов, перков и персонажей. Также подключены два каталога в группе «Навыки и владения»; см. [06-skills-and-proficiencies.md](06-skills-and-proficiencies.md). Эффекты настраиваются внутри перков и магических предметов; см. [10-effects.md](10-effects.md). Иконки четырёх характеристик редактируются через отдельную кнопку над таблицами.

Новая версия ещё не установлена на рабочий форум. Перенос данных и переключение пакета — отдельный согласованный шаг. Выполненные тесты создают собственные таблицы с уникальным префиксом и затем удаляют только их.

## Структура интерфейса

~~~text
js/src/admin/
  components/RoleplayPage.tsx             навигация
  catalog/
    definitions/                        описание каждого раздела
    components/                         общие таблица, окно и элементы формы
    CatalogApi.ts                       HTTP-запросы
    CatalogListState.ts                 поиск, фильтры и загрузка
    CatalogEditorState.ts               независимый черновик и сохранение
  editors/                              поля конкретных сущностей

js/src/common/
  catalogData.ts                        типы данных и преобразования
  presentation.ts                       урон, римские числа, время
  cards/                                карточки compact и expanded
  uiIcons.ts                            оформление и локальные замены
~~~

Каждый файл в definitions описывает заголовок, значок раздела, колонки, фильтры, начальные значения формы и нужный редактор. Страница не содержит проверки полей расы, предмета или заклинания.

Таблица, поиск, пагинация, переключатель статуса и окно сохранения общие. Поля и компоновка редакторов остаются отдельными: редактор расы не превращается в набор условных полей универсальной формы.

Кнопки создают настоящую HTML-форму с submit. Окна импортируются напрямую; для их открытия не требуется подгрузка отдельного чанка. Адаптер showModal ограничивает обход несовместимости типов Flarum одной небольшой границей.

## Серверная часть

~~~text
src/Api/
  AdminCatalogController.php             общий HTTP-контракт справочников
  AdminCharacterController.php           таблица и правка персонажа
  UploadPerkImageController.php           загрузка изображения перка

src/Catalog/
  Shared/
    CatalogRegistry.php                 закрытый реестр доступных справочников
    AbstractCatalog.php                 общие операции и типы JSON-ответа
    DefinitionStore.php                 SQL, поиск, пагинация и запись
    CatalogRevision.php                 согласованная версия справочников
    CatalogUsage.php                    зависимости при удалении
    FieldValues.php, AbilityValues.php  общие проверки
  Races/RaceRules.php                    структура расовых бонусов и выборов
  остальные папки                       проверки полей конкретных сущностей

src/Character/Admin/CharacterAdmin.php   изменение имени и литературной ссылки
src/Presentation/PerkImageEncoder.php    обработка SVG, PNG и WebP
~~~

Все административные операции проверяют права администратора. Модераторские действия в профилях сюда не добавлены.

Общий API:

~~~text
GET     /roleplay/admin/catalogs/{catalog}
POST    /roleplay/admin/catalogs/{catalog}
PUT     /roleplay/admin/catalogs/{catalog}/{id}
PATCH   /roleplay/admin/catalogs/{catalog}/{id}
DELETE  /roleplay/admin/catalogs/{catalog}/{id}
GET     /roleplay/admin/characters
PUT     /roleplay/admin/characters/{id}
POST    /roleplay/admin/perk-image
~~~

Список возвращает строки, количество, страницу, версию и связанные определения для селекторов. Имена таблиц и классов никогда не формируются из произвольной строки запроса.

Сохранение получает весь черновик fields и ожидаемую revision. Статус меняется отдельным PATCH и сразу сохраняется. У справочников общая версия, поэтому ссылки и определения проверяются под одной блокировкой. У каждого персонажа собственная версия: правка имени не конфликтует с изменением справочника.

При конфликте окно сохраняет введённые значения и показывает ошибку. Для повторения нужно обновить список и открыть актуальную запись. Старый ответ поиска не заменяет новый результат. Повторное нажатие сохранения не отправляет второй запрос.

## Согласованные данные и ограничения

| Раздел | Содержимое |
| --- | --- |
| Расы | Возраст, фиксированные бонусы, бонусы на выбор, фиксированные и выбираемые перки, заклинания и выбор из путей |
| Пути магии | Название, описание, класс иконки, HEX-цвет, статус |
| Типы предметов | Иконка, описание, признак оружия, лимит экипировки |
| Источники перков | Собственная подпись/иконка либо зависимость; для навыков — переопределения четырёх иконок |
| Заклинания | Путь, круг, дистанция, радиус, длительность, числовой урон, время наложения, перезарядка и затраты |
| Предметы | Тип, редкость, внешность, магический индикатор, урон, цена, вес, стопка, текстовые свойства со своей перезарядкой |
| Перки | Название, описание, изображение, редкость; без типа, признаков и общего источника |
| Персонажи | Список с игроком, расой и статусом; правка имени, фамилии и литературной ссылки |

У типа предмета −1 запрещает экипировку, 0 означает отсутствие лимита. Отсутствующий вес сохраняется как 0. Выключение определения не удаляет его из персонажей. Удаление используемой записи отклоняется с понятной ошибкой; учитываются также ссылки внутри правил рас.

У каждой выдачи перка один источник. Поэтому один и тот же перк может иметь разные источники у разных персонажей. Поля source_id и source_context находятся у выдачи, а не у определения перка. «Создание персонажа» источником не является. В предпросмотре определения перка полоса остаётся пустой — источник будет передан из конкретной выдачи.

Фиксированные расовые заклинания заданы как дополнительные выдачи без требования Магии 3. Выбор заклинания из пути хранится отдельно и не считается автоматической выдачей. Админка сохраняет эти правила; исполнение выдач будет подключено к мастеру.

Свойства предмета и описания остаются обычным текстом: их можно выделять и копировать. Числовые бонусы не извлекаются автоматически из фразы в описании.

Урон хранится числом: 1, 3, 9, 27 и 81 соответствуют ступеням. Форматирование, например 14 → «Средний + Малый + Незначительный ×2», выполняется только при выводе.

Изменение литературной ссылки сохраняет одобрение и статус. Ссылка проверяется на существующую доступную тему данного форума. Создание персонажа и его развитие не относятся к этому редактору.

В разделе «Персонажи» администратор может удалить выбранного персонажа после подтверждения. DELETE `/api/roleplay/admin/characters/{id}` принимает его собственную `revision`; устаревшая строка отклоняется. `CharacterAdmin::remove()` блокирует владельца и персонажа и одной транзакцией удаляет характеристики, навыки, владения, перки, заклинания, предметы, выборы, балансы и события. Аккаунт, литературная тема, справочники и независимый черновик создания остаются. Технические UUID операций сохраняются с пустым `character_id`, чтобы запоздалый повтор создания не восстановил удалённого персонажа.

Текст подтверждения задаётся в `Characters.tsx` через `removeConfirmation`, как и остальные возможности раздела. Общая таблица берёт версию удаления из `definition.revision`, поэтому для справочников отправляется версия каталога, а для персонажа — версия строки. `tests/check-character-delete.php` проверяет права, конфликт версии, очистку связанных записей, сохранность второго персонажа и защиту старого запроса создания на временных таблицах.

## Где самостоятельно менять

| Что менять | Файл или место |
| --- | --- |
| Колонки и фильтры раздела | js/src/admin/catalog/definitions/соответствующий файл |
| Набор полей и расположение формы | js/src/admin/editors/соответствующий редактор |
| Проверки и допустимые поля | src/Catalog/соответствующий класс, validate() |
| Общие пределы и единицы времени | Shared/FieldValues.php, Shared/AbilityValues.php |
| Геометрию карточек | js/src/common/cards/EntityCardFrame.tsx и resources/admin.css |
| Цвета редкости | resources/presentation/rarities.json |
| Служебные значки | resources/presentation/icons.json |
| Значки сущностей и цвета путей | Соответствующие административные редакторы |
| Локальную замену Pro-иконок | resources/presentation/icons.local.json; подробнее в 03-icons.md |
| Бонусы и выборы расы | Редактор расы; структура проверки в Races/RaceRules.php |

В миграции находятся только таблицы и ограничения. Первая миграция дополнена, поскольку новая версия ещё не была установлена. Этот подход не является инструкцией переписать применённые миграции старого форума.

Четыре стартовые характеристики, одиннадцать выключенных навыков и шесть владений добавляет SeedBaseCatalogs из resources/defaults/base-catalogs.php. Повторный запуск добавляет только отсутствующие записи и сохраняет настроенные администратором значки. Само наполнение и перенос остальных данных выполняются при будущем согласованном переключении.

## Проверки и их границы

Проверены:

- Чистая схема, откат и повторная установка на временных таблицах.
- API всех справочников, повторное сохранение загруженной формы, фильтры, версии, права и удаление с зависимостями.
- Различные источники одного перка, сохранение изученных заклинаний при выключении пути.
- Правка персонажа с сохранением одобрения и статуса.
- Обработка SVG без записи изображения в рабочие assets.
- Настоящая клиентская сборка: таблицы, редакторы, вложенные карточки и открытие окон с правилами нормализации Mithril.
- Защита от повторного сохранения и запоздавшего ответа поиска.
- Иконки в JS, PHP и метаданных при включённых, выключенных и отсутствующих локальных заменах.

Команды из корня проекта:

~~~text
docker compose exec -T forum php packages/roleplay-new/tests/check-foundation.php
docker compose exec -T forum php packages/roleplay-new/tests/check-base-catalogs.php
node packages/roleplay-new/tests/check-admin-client.cjs
node packages/roleplay-new/tests/check-local-icons.cjs
~~~

Клиентским тестам нужна локальная карта исходников уже установленного ядра:

~~~text
docker cp questpost-dev-forum-1:/var/www/html/vendor/flarum/core/js/dist/admin.js.map packages/roleplay-new/tests/.runtime/core-admin.js.map
~~~

Перед копированием создайте папку tests/.runtime. Имя контейнера берётся из вашей локальной конфигурации. Папка игнорируется и не входит в архив. Тест использует Mithril из этой карты, а компоненты ядра заменяет небольшими адаптерами. Это проверяет создание разметки и обработчики, но не является визуальной проверкой в браузере.

Рабочая админка пока остаётся на старом пакете. Дальнейшее подключение мастера, профиля, прокачки и модераторских действий требует отдельного плана.
Обновление следующего этапа: эффекты и защита брони подключены через CharacterCalculationBuilder; см. [эффекты](10-effects.md). Снимок состояния по-прежнему хранит приобретённые уровни и сам не рассчитывает бонусы.

Сервер создания, стартовые выдачи, балансы и права выбора: [12-character-creation.md](12-character-creation.md).
