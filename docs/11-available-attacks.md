# Доступные атаки: архитектура и места настройки

Этап выполнен только в roleplay-new. Новый пакет не установлен; рабочие данные и старое расширение не менялись.

## Согласованные правила

У предмета три независимых применения: ближнее от Физиологии, от Ловкости, магическое. Каждое отмеченное применение требует своего выбранного владения. Зачарованный меч может требовать одноручного владения для обычной атаки и магического для магической. Наличие одного не разрешает другой способ.

Для Ловкости существует один вариант и один показатель: дальнобойная атака и атака метательным оружием в ближнем бою рассчитываются одинаково. Дополнительная классификация дальнего/метательного оружия не добавлена.

Связь задаётся числовым ID записи из каталога «Владения». Название, системный ключ, тип предмета и его описание не определяют владение. Каталог можно переименовать без изменения привязки. Используемое владение нельзя удалить. Снятая галочка скрывает поле; сохранённая привязка не участвует в расчёте, но остаётся для повторного включения.

Оружие без нужного владения исключается из доступных атак. Безоружный вариант и эффекты с условием «Без оружия» доступны, если не экипировано оружие ближнего боя (`is_melee_weapon`). Даже неосвоенный меч отключает этот вариант. Дальнобойное, метательное и магическое оружие без признака оружия ближнего боя, а также плащ и броня его не блокируют. Если предмет имеет несколько оружейных признаков, наличие `is_melee_weapon` всё равно отключает безоружный вариант.

Каждый экземпляр и каждое применение считаются отдельно. Два меча не дают сумму урона. Для анкеты выбирается максимум отдельной атаки каждого вида.

Изученное заклинание с damage_units > 0 добавляет вариант от Магии. При нулевом уроне вариант не создаётся: базовая Магия не превращает вспомогательное заклинание в атаку. Выключенные заклинания/пути остаются в приобретённом состоянии. Повторные проверки круга, владения магическим оружием, маны, перезарядки и времени наложения здесь не выполняются: в том числе сохраняется действие фиксированных расовых заклинаний, выданных без требования Магии 3.

## Поток данных

1. CharacterSnapshotBuilder готовит согласованный снимок приобретённых характеристик, владений, заклинаний и имущества.
2. CharacterAttackBuilder читает экипировку, проверяет соответствующее владение и собирает варианты атак. Затем добавляет полученные заклинания с уроном.
3. CharacterCalculationBuilder собирает эффекты, вычисляет значения характеристик и привязывает эффекты оружия к ID экземпляра.
4. Существующий CharacterCalculator / AttackCalculator считает каждый вариант и выбирает максимум.

Внешний экран вызывает CharacterCalculationBuilder::defaults()->calculate($snapshot). Передавать произвольный список атак сюда больше не нужно. Для изолированных математических проверок остаётся низкоуровневый CharacterCalculator.

Сборщик атак не выполняет SQL, не выдаёт владений, не изменяет персонажа и не разбирает текст свойств. Бонус характеристики не открывает новые владения, навыки и круги.

Название и принадлежность конкретного владения задаются в админке. В JSON нет ID игровых записей. Изменение подписи не требует миграции. Добавление нового поля/механики требует серверной реализации и изменения схемы, одной строки JSON недостаточно.

В единственной ещё не установленной базовой миграции добавлены три nullable FK у предмета: melee_proficiency_id, ranged_proficiency_id, magic_proficiency_id. CHECK требует заполненную привязку для каждого отмеченного применения. Порядок создания и удаления таблиц учитывает новые зависимости. Иконки, названия и значения игровых владений в миграцию не добавлялись.

## Результат и источники

Сохраняется прежний формат attacks и maximum_damage. ID атаки предмета: item:<ID экземпляра>:<способ>. Источник содержит kind = item, id экземпляра, definition_id определения и proficiency_id. Разные применения одного экземпляра имеют разные ID атак, но один ID источника — локальный эффект может действовать на соответствующие атаки этого экземпляра.

ID атаки заклинания: spell:<ID выдачи>. Источник содержит kind = spell, id выдачи, definition_id определения, magic_path_id и level. Служебный безоружный вариант имеет ID unarmed.

Отсутствие доступного варианта означает null в maximum_damage, а не нулевой базовый вклад характеристики.
В этом случае анкета отображает base_damage: например, урон от Ловкости без экипированного оружия.
Это отображение базы не выдаёт владение и не разрешает применение оружия без него.
Урон форматируется существующей функцией presentation.damage(); суммы заново нормализуются по правилу 3:1.

## Проверки и границы этапа

- check-available-attacks.php: оружие без владения, безоружное условие, два применения зачарованного меча, один вариант от Ловкости, два оружия, полученные заклинания и повреждённые снимки. В памяти, без БД.
- check-base-catalogs.php: настоящие CRUD/API, три типизированные привязки, неизвестное/отсутствующее владение, запрет удаления, чтение реальных выдач и экипировки, локальные эффекты разных экземпляров, откат и повторное создание схемы. Только отдельные временные таблицы.
- check-admin-client.cjs: поля появляются по отмеченным применениям; три быстрых изменения сохраняются независимо; снятие галочки скрывает только своё поле.
- Прежние проверки формул, эффектов и развития сохранены.

Профиль, мастер создания, выдача/повышение навыков и владений, операции экипировки, магазин и боевые действия остаются отдельными следующими этапами. Эта подсистема подготавливает данные для них.

Сервер создания, стартовые выдачи, балансы и права выбора: [12-character-creation.md](12-character-creation.md).
