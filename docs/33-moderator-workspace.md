# Основная модераторская

Реализовано 28 октября 2026 года на локальном форуме.
Это рабочая вкладка собственного профиля аккаунта, без выбора персонажа.
Адрес: `/u/{username}/moderation`. В чужом профиле рабочее пространство не открывается.

## Доступные разделы

- **Мои эпизоды**: истории, где текущий сотрудник назначен единственным ведущим
- **Перки**, **Заклинания**, **Предметы**: существующие справочники карточками

В эпизодах по умолчанию выбраны текущие ролевые истории. Есть архив и отдельный
фильтр обычных форумных событий. Показаны статус, число участников и сами участники.
Для персонажей предусмотрен переход к их анкетам, где остаются существующие
действия проверки и выдачи. Назначение ведущим не добавляет прав управления:
кнопка «Управление» открывает существующий редактор события только при наличии
прежнего права `quest-events.manage`.

Список использует прежние записи встроенного модуля Events. Отдельных таблиц
эпизодов нет. Сервер выбирает ведущего по текущему аккаунту, а не по присланному
идентификатору пользователя, и сохраняет проверку видимости исходного сообщения.

Справочники используют те же карточки, что профиль, мастер и правила,
а создание и редактирование открывают общий `CatalogEditModal` с существующими
редакторами и загрузкой изображения. Поиск, фильтры, страницы, проверка версии,
валидация полей и защита используемых записей от удаления не дублируются.

## Права

В штатной таблице разрешений Roleplay зарегистрированы:

| Право | Назначение |
| --- | --- |
| `roleplay.workspace` | Открывать собственную модераторскую |
| `roleplay.catalog.view` | Просматривать три рабочих справочника |
| `roleplay.catalog.create` | Создавать записи |
| `roleplay.catalog.edit` | Изменять любые записи этих справочников и переключать их доступность |
| `roleplay.catalog.delete` | Удалять неиспользуемые записи |

Для действий со справочниками нужны доступ к модераторской и право просмотра,
а для записи — соответствующее отдельное право. Создание не даёт редактирование,
редактирование не даёт удаление. Удаление используемых записей запрещено прежними
проверками `CatalogUsage`.

Миграция по умолчанию даёт группе Moderator только открытие модераторской
и просмотр. Создание, редактирование и удаление администратор назначает группам
отдельно. Также требуется существующий доступ к форуму и ролевой.
Администраторы используют обычные полномочия Flarum.

В восстановленной локальной копии стандартная группа Moderator (ID 4) отсутствует,
поэтому начальные назначения для неё штатно пропущены. Сейчас рабочее пространство
доступно администраторам. Для других групп администратор выбирает перечисленные
права в разрешениях Roleplay; существующие пользовательские группы автоматически
модераторами не объявляются.

Новые права не открывают административные HTTP-маршруты и не разрешают изменение
рас, характеристик, путей магии, настроек мастера или других справочников.
Прежнее создание перков, заклинаний и предметов из окна выдачи по праву
`roleplay.moderate` сохраняется. Общая загрузка изображения также поддерживает
сотрудника с правом редактирования рабочего справочника.

## Где менять поведение

| Часть | Путь |
| --- | --- |
| Границы прав | `src/Workspace/WorkspaceAccess.php` |
| Список и операции справочников | `src/Api/WorkspaceCatalogController.php` |
| Связь с общими справочниками | `src/Catalog/Shared/CatalogRegistry.php`, `DefinitionStore.php` |
| Собственные эпизоды | `src/Api/WorkspaceEpisodesController.php` |
| Права в админке | `js/src/admin/index.ts` |
| Профиль, вкладки, каталог и список эпизодов | `js/src/forum/workspace/` |
| Стили расположения | `resources/workspace.css` |

Стили карточек и формы редакторов остаются в общих файлах. Рабочая вкладка
задаёт только сетку, фильтры и управляющие кнопки. В рабочем списке используются
более плотные размеры: 104 px основной блок и 24 px нижняя полоска.
На широком экране — три колонки, до 1199 px — две, до 767 px — одна.

## Проверки

- `tests/check-workspace.php`: недоступность гостю и обычному игроку, отдельные
  права операций, запрет других справочников и административных маршрутов,
  общая валидация и версия, защита используемого предмета, собственные эпизоды,
  фильтр форумных событий и архив. Все временные изменения откатываются
- `tests/check-workspace-client.cjs`: карточки и фильтры, отсутствие недоступных
  кнопок, общий редактор, открытие собственного профиля и граница чужого профиля
- `tests/check-admin-client.cjs`, `tests/check-management-client.cjs`: прежние
  административные редакторы и выдача из анкеты
- Проверка типов и производственная сборка
- Браузер: собственная вкладка, карточки, фильтрация заклинаний по пути магии,
  открытие редактора без сохранения изменений

Пока не реализованы тикеты, база мира, новый BB-код завершения с наградами,
BB-коды проверок и обучение по литературе. Эти части остаются отдельными
блоками [плана первого выпуска](development-plan-2026-10-28.md).
