# Отдельный визуальный стенд мастера

Стенд запущен на http://localhost:4173. Форум для правки оформления перезагружать не требуется.

## Что можно проверить

- Все семь шагов можно открыть кнопками верхней панели, не заполняя предыдущие.
- Ширины 320, 480, 620, 708 и 980 px, а также всё доступное окно.
- Окно мастера шириной 620 px: содержимое прокручивается, кнопки и шкала шагов остаются на месте.
- Обычный пример, пустую форму, длинные описания и достигнутый лимит выбора.
- Прибавление и сохранение характеристик, выбор карточек, зелёную рамку и галочку.
- Повторный клик снимает выбор и освобождает лимит.
- Кнопка «Сбросить пример» возвращает исходные вымышленные данные.

При сохранении CSS меняется оформление без перезагрузки формы. Изменения TypeScript автоматически пересобираются и перезагружают экран стенда; демонстрационный черновик сохраняется в sessionStorage этой вкладки. Сброс очищает текущий пример.

Это визуальный стенд. Здесь нет входа, запросов к API форума, сохранения в базе и создания настоящих персонажей. Списки доступных выборов и итоговые числа — подготовленные примеры, а не копия серверного расчёта правил. Игровые требования, пороги и цены по-прежнему проверяются серверными тестами.

## Где менять оформление

| Файл | Назначение |
| --- | --- |
| resources/forum.css | Отступы мастера, поля, кнопки характеристик, сетки и адаптация |
| resources/cards.css | Карточки перков, заклинаний, предметов и состояния выбора |
| js/src/forum/creation/CreationWizardForm.tsx | Общая разметка мастера |
| js/src/forum/creation/steps/*.tsx | Разметка конкретного шага |
| resources/presentation/icons.json | Единый список интерфейсных иконок |
| resources/presentation/icons.local.json | Локальные замены недоступных Pro-иконок |
| preview/build-fixture.cjs | Понятно подписанные вымышленные примеры |
| preview/fixtures/wizard.json | Подготовленный набор данных стенда |
| preview/base.css | Только замена базового окружения Flarum: шрифт, кнопки, переменные темы |
| preview/preview.css | Только верхняя панель и окно стенда |

После изменения icons.local.json перезапустите стенд: локальные замены встраиваются при запуске сборки. Основной icons.json обновляется автоматически.

После изменения build-fixture.cjs нужно выполнить:

    node preview/build-fixture.cjs

из корня пакета. Изменение полученного JSON автоматически пересоберёт стенд. Эта команда ничего не импортирует в форум.

## Архитектура

Окно форума CreationWizardModal подключает общую CreationWizardForm, реальную сессию, CreationApi и переход к анкете. Стенд подключает ту же CreationWizardForm и CreationState, но передаёт DemoTransport с вымышленными данными. Все шаги, карточки и общая анкета используются напрямую из production-кода.

Четыре небольших адаптера в js/preview заменяют только оболочку Flarum Component, Button, LinkButton и Icon. Они не содержат игровой логики. preview/base.css приближает стандартное окружение Flarum: пользовательская тема конкретного форума может повлиять на итоговое оформление, поэтому последняя проверка на форуме всё равно нужна.

Сервер preview/server.cjs собирает отдельный preview.js в tests/.runtime/preview-dist. Обычные admin.js и forum.js не затрагиваются. Файлы выдаются по явному списку; содержимое tests/.runtime, отчёты и копии базы по HTTP недоступны. Сервер слушает только 127.0.0.1.

## Повторный запуск

Из папки packages/roleplay-new/js:

    npm run preview

Если Node отсутствует в PATH, из корня рабочего проекта:

    & 'C:\Users\KusoT\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' packages/roleplay-new/preview/server.cjs

При первом запуске сервер берёт только шрифты и карту JS ядра из тестового контейнера questpost-roleplay-test-forum-1. Дальше эти файлы используются из локального кеша. Docker нужен при первой подготовке кеша; форум не нужен для последующей работы над оформлением.

Остановить — Ctrl+C в терминале, в котором запущен сервер. Если порт занят, можно задать ROLEPLAY_PREVIEW_PORT перед запуском.

## Исправление сброса характеристик

PHP ранее выдавал пустые именованные карты base_attributes и loadout как JSON-массивы []. Форма добавляла в массив свойства physiology и gear; JSON.stringify пропускал такие свойства. После ответа сохранения выбор исчезал.

CreationDraftController теперь выдаёт эти карты объектами {}, даже если они пустые. CreationState также нормализует их при загрузке и после сохранения: это защищает уже существующие черновики и старые ответы. Очередь сохранения не менялась.

Проверки:
- TypeScript основной сборки и стенда;
- производственная сборка JS;
- клиентский сценарий с первоначальными [] и реальной сериализацией запроса;
- серверный сценарий формы JSON пустых карт на временных таблицах;
- браузер: семь шагов, сохранение после прибавления, лимит/снятие выбора, загрузка ресурсов и адаптация до 320 px.
## Начертания и полоска прогресса

По уточнению макетов используем Arial: семейство задаётся один раз в переменной --rp-wizard-font внутри .RpWizard в resources/forum.css.

- Заголовок мастера: 27 px, обычное начертание 400.
- Подписи полей, счётчики, названия групп и основные кнопки: 16 px, жирное начертание 700.
- Значения полей и инструкции: 16 px, обычное начертание 400.
- Названия карточек и параметры: заданные компактные размеры, жирное начертание.
- Вспомогательные подписи: обычное начертание и вторичный цвет темы; описание карточек — немного плотнее обычного (500 и тонкий контур для Arial).
- При ширине до 580 px заголовок уменьшается до 22 px.

Полоска прогресса использует отдельный RpWizard-progressLine перед каждым значком. Он относится к следующему шагу и принимает его активное/неактивное состояние. Линия и значок не накладываются друг на друга; после последнего значка есть завершающая линия. Длина линии — 13 px, зазор после иконки — 6 px. На телефоне — 9 и 5 px соответственно. Закруглены только внешние концы первой и последней линий.

Ширина значков и линий, зазоры и мобильный вариант задаются рядом с .RpWizard-progress. Служебные иконки по-прежнему настраиваются в resources/presentation/icons.json. Значок шага характеристик — fa-chart-simple с вертикальными столбиками.

## Геометрия карточек

Оформление всех трёх сущностей находится в resources/cards.css. EntityCardFrame задаёт общую структуру; PerkCard, SpellCard и ItemCard передают содержимое и тип карточки.

Размеры меняются через переменные --rp-card-* в начале файла. Для мастера и профиля отдельный блок переопределяет только эти переменные: основной блок всех трёх типов — 86 px, нижняя полоса — 24 px. В редакторе используются более крупные размеры. Не нужно дублировать эти правила в resources/forum.css.

Название и верхние параметры находятся в одной строке: название слева, параметры справа. Его название окрашено в цвет пути. Названия и параметры жирные, описание приглушённое, немного плотнее обычного. Для Arial используются вес 500 и контур 0.12 px; полужирное начертание не применяется. Длинное описание прокручивается, длинное название сокращается в одной строке и полностью доступно при наведении. Источник выводится прописными буквами, урон — иконкой и величиной без слова «УРОН».

Затраты, вес и цена объединены в RpCard-resources; в expanded группа прижата вправо. Нижняя полоса сохраняет высоту и без урона или источника. Значок урона настраивается ключом fields.damage в resources/presentation/icons.json, без миграций.
Иконка типа предмета в обоих представлениях помещена в белый круг. В expanded под верхней строкой гарантированно помещаются три строки описания; остальное доступно прокруткой.

Маркер магического предмета располагается справа снизу основной иконки, внутри отдельного светло-серого круга. Иконка чёрная. Силуэт четырёхлучевого sparkle задаётся векторной маской класса rp-icon-sparkle в resources/cards.css; ключ item.magical в icons.json выбирает этот класс. Font Awesome Pro для него не требуется. Круг одинаково используется в compact и expanded, уменьшаясь вместе с основной иконкой.

Название явно использует Arial 700 и контур 0.18 px: это делает жирное начертание заметнее на небольшом размере. Толщина контура задаётся в правиле .RpCard .RpCard-heading > strong, отдельно от уплотнения описания.
