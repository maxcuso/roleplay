# Мастер создания: интерфейс и дополнительные расовые владения

Мастер открывается в окне шириной 620 px из тегов «Ролевая» / «Анкеты» и профиля.
Отдельного маршрута `/roleplay/create` больше нет. Текущий и пройденные шаги заметные,
будущие — бледные. Полоска шагов и нижние кнопки остаются на месте, прокручивается содержимое.
На телефоне окно занимает почти весь экран.

Закрытие крестиком, Escape или кликом по фону дожидается сохранения черновика.
Если сохранить не удалось, ввод остаётся в открытом окне; можно повторить сохранение или явно закрыть без него.
Повторное открытие загружает сохранённый шаг. После создания открывается новая анкета в профиле.
При редактировании технической части применяется та же форма, но сам персонаж меняется только после финального подтверждения.

## Сценарий и макеты

Семь шагов: общие сведения → характеристики → навыки/владения → перки → заклинания → снаряжение → итог.

На первом шаге показываются имя, фамилия, возраст, раса и её фиксированные бонусы. Стрелка рядом с расой открывает настроенную страницу правил в новой вкладке. Без ссылки стрелка не выводится.

Характеристики распределяются кнопками ±. Интерфейс показывает остаток очков, расовые прибавки и приобретённые итоги. Игрок свободно распределяет 7 очков, каждое начальное значение — от 1 до 3 до расовых прибавок. Кнопки ограничивают запас и границы, сервер проверяет их повторно; промежуточные значения могут быть незавершёнными.

Навыки и обычные владения сгруппированы по характеристикам. Сервер возвращает отдельный список вариантов для каждого достигнутого порога. Можно оставить обычный выбор на будущее. После замены раннего выбора навыка его последующие повышения сбрасываются; выборы другой характеристики сохраняются.

Карточки горизонтальные, по две в строке; до 480px — по одной. Выбранная карточка имеет зелёную рамку и круглую зелёную галочку справа сверху. Повторное нажатие снимает выбор. При достижении лимита невыбранные карточки отключаются; выбранные остаются доступными для снятия. Enter и пробел работают с клавиатуры. Выделение текста описания не переключает выбор.

В перках сверху показаны выдаваемые способности, ниже — расовый выбор. В заклинаниях отдельно показаны автоматические, расовый выбор и обычный выбор. В снаряжении каждая группа имеет свой лимит; автоматические наборы показаны без выбора. Итог оформлен общей анкетой с реальными расчётами ресурсов, урона, защиты и веса.

## Настройка расовых владений

В редакторе расы появились:

- «Сколько владений выбрать» — proficiency_choice_count; 0 отключает блок.
- «Доступные владения» — proficiency_choice_mode: all или list.
- Список определений — proficiency_choice_ids, используется в режиме list.
- «Ссылка на правила расы» — rules_url, полная HTTP/HTTPS-ссылка без логина и пароля.

Для полуэльфа: mode = all, count = 1. Для дварфа: mode = list, count = 1, список ID одноручного и двуручного владений. Названия рас и конкретные ID не зашиты в код и не добавляются в миграцию.

Расовый выбор не проверяет уровень характеристики и не расходует обычные пороговые права. Используется только включённое определение владения из разрешённого расой списка. Полученное автоматически или ранее выбранное обычным способом владение не предлагается повторно. Сначала учитываются автоматические владения, затем расовый выбор, затем обычное обучение; дубликаты не создают вторую выдачу.

Поле черновика racial_proficiency_ids отделено от proficiencies. Количество и список проверяются сервером при сохранении предпросмотра и снова при окончательном создании. Реальная выдача использует существующую CreationGrants и общую транзакцию. Расовый выбор обязателен, если у расы count > 0; возможность оставить выбор на будущее относится к обычным пороговым правам.

Удаление владения из каталога блокируется, если оно используется в расовом списке. Выключение сохраняет определения и уже полученные владения, но запрещает новое получение.

## Одна система правил и расчётов

CreationOptions использует DevelopmentRules, SkillEligibility, ProficiencyEligibility и TrainingCreationPlan. Варианты повышения строятся по состоянию ДО соответствующего выбора: уже выбранный III уровень можно редактировать без ошибочного сообщения «навык на максимуме». Интерфейс не содержит второй таблицы порогов.

CreationValidator разделяет ошибки общих сведений и распределения характеристик. Благодаря этому первый шаг не требует заполнить будущие шаги.

CreationReview собирает CharacterSnapshot в памяти из доверенного плана и вызывает CharacterCalculationBuilder. Эффекты перков, доступные заклинательные атаки, максимумы ресурсов и вес рассчитываются тем же кодом, который используется для персонажа. Предпросмотр не делает выдач и не выполняет SQL. Стартовые вещи не экипируются автоматически; их эффекты в итог не применяются до экипировки.

## Сохранение и ошибки

Ввод сохраняется с задержкой 600ms. Одновременно идёт один запрос; ввод во время запроса отправляется следующим с новой версией. Старый ответ не заменяет последний ввод.

Перед переходом мастер сохраняет черновик и получает серверный предпросмотр. Назад можно перейти и при незавершённом текущем шаге. Дальше — только после завершения предыдущих шагов.

Конфликт двух вкладок останавливает автосохранение. Локальный ввод остаётся на экране; кнопка «Загрузить сохранённый черновик» явно загружает актуальное состояние. Изменение справочников также требует загрузить их актуальную версию.

После изменения расы/характеристик/справочников недоступные выбранные способности остаются доступными для снятия. Для ошибочного обычного обучения есть отдельные кнопки сброса навыков и владений. Устаревшие варианты/группы вещей также можно убрать.

Повтор создания после потери ответа отправляет тот же operation_key и те же версии. Двойное нажатие во время запроса отключено. После успеха мастер показывает подтверждение и имеющийся итог; после повторной загрузки сервер сообщает об уже созданном персонаже и блокирует новую выдачу. Переход на страницу профиля подключён следующим этапом; см. документ 14.

## Где редактировать

- Порядок, подписи и ключи иконок шагов — types.ts.
- Конкретный экран — соответствующий steps/*.tsx.
- Размеры, отступы и ширина перехода к одной колонке — forum.css.
- Общие карточки — common/cards и cards.css.
- Иконки — icons.json; локальные замены Pro-иконок — icons.local.json, без миграций.
- Расовые бонусы/списки/количество/ссылка — редактор расы.
- Конкретные стартовые предметы и золото — серверные настройки создания, см. документ 12.

Новая колонка rules_url добавлена в единственную базовую миграцию ещё не установленного пакета. Миграция не содержит ссылок, иконок, полуэльфа или дварфа как игровых данных.

## Проверки и ограничения

Серверные сценарии работают на временных таблицах с отдельным проверенным префиксом. Проверяются свободное и ограниченное расовые владения, отсутствие требований Магии, дубликаты, автоматическая выдача, реальное сохранение через API, варианты III ранга, независимость первого шага от будущих и общий расчёт веса/ресурсов.

Клиентский тест tests/check-creation-client.cjs использует вымышленные данные из tests/.runtime/creation-view.json, сформированные серверным сценарием. Он раскрывает все семь шагов настоящим Mithril, проверяет рамку/галочку, клавиатуру, отключённые карточки, устаревшие выборы, очередь сохранения, конфликт и повтор создания. Это проверка поведения и разметки, а не визуальная проверка в браузере.

Проверки запускаются после сборки нового JS. Для клиентского стенда нужна локальная карта tests/.runtime/core-admin.js.map установленного ядра Flarum; она не публикуется вместе с пакетом.

Пакет пока не установлен; новые каталоги ещё нужно заполнить и привязать стартовые наборы. Профиль и экипировка реализованы следующим этапом (документ 14). Интерфейс администрирования стартовых наборов, литературная анкета/модерация и последующая прокачка остаются отдельными этапами.
