# Иконки: согласованная схема настройки

## Места настройки

1. resources/presentation/icons.json — служебные значки всех экранов.
2. Справочники БД — иконки характеристик, путей, типов предметов и источников; изображение перка.
3. resources/defaults/base-catalogs.php — начальные значения для новой установки.

В миграциях есть колонки icon, но нет названий значков и начального оформления.

## Как менять служебную иконку

Например, actions.save отвечает за сохранение, permissions.view — за право просмотра, resources.mana — за обозначение маны. Заменяешь значение соответствующего ключа и пересобираешь интерфейс. Ключ оставляешь прежним: к нему обращается код.

Разделы файла: permissions — права; sections — разделы; actions — действия; resources — ресурсы; combat — показатели боя; fields — обозначения полей. Значения сейчас перенесены из существующего оформления; доступность нужного набора Font Awesome проверяем при подключении экранов.

Пока каркас использует только permissions.view и permissions.create. Остальные ключи подготовлены для следующих компонентов; соответствующие экраны ещё не реализованы.

Из папки js:
~~~text
pnpm typecheck
pnpm build
~~~

Текущий локальный проект также допускает запуск установленных инструментов Node напрямую, как в предыдущих шагах.

## Использование в коде

JavaScript/TypeScript:
~~~typescript
import {uiIcon, catalogueIcon} from '../../common/uiIcons';

// Служебный значок.
const saveIcon = uiIcon('actions.save');

// Значение от игрового справочника; при отсутствии — общий нейтральный значок.
const itemIcon = catalogueIcon(itemType.icon);
~~~

Путь импорта зависит от папки компонента. TypeScript проверяет наличие служебного ключа.

PHP:
~~~php
$icons = new \Maxcuso\Roleplay\Presentation\InterfaceIcons();
$saveIcon = $icons->get('actions.save');
$itemIcon = $icons->catalogue($itemType->icon);
~~~

Неправильный служебный ключ вызывает ошибку: она помогает найти опечатку. Отсутствующая иконка сущности даёт fallback. Ни PHP, ни JavaScript не подбирают оформление по имени сущности или её slug.

## Значок расширения в списке Flarum

Ключ extension является источником значения. Сборка переносит его в extra.flarum-extension.icon.name в composer.json — обязательное поле метаданных Flarum. Вручную имя значка в Composer редактировать не нужно.

После установки/обновления пакета метаданные значка должны быть обновлены в установленном Composer-пакете и кэше форума. Одной пересборки JavaScript для метаданных уже установленного пакета недостаточно. Миграция БД не требуется.

## Игровые сущности

Иконки сущностей хранятся в справочниках. Когда подключим редакторы и API новой версии, они будут редактироваться через справочники и приходить в ответах API. Для такой замены пересборка интерфейса не потребуется. Начальное наполнение лишь добавляет отсутствующие определения; изменение файла defaults не перезаписывает уже заданные значения.

Проверки этого шага не устанавливают новую версию расширения, не подключают новые маршруты и не изменяют миграции.
Проверено: TypeScript, production-сборка, синтаксис PHP, чтение всех служебных ключей из общего файла, fallback для отсутствующей иконки сущности и совпадение значка расширения с метаданными Composer.

## Локальные замены Pro-иконок

Файл resources/presentation/icons.local.json существует только у разработчика.
В текущей рабочей копии он создан и включён. В Git и Composer-архив он не входит.
Образец для другой машины: resources/presentation/icons.local.example.json.

~~~json
{
  "enabled": true,
  "replacements": {
    "fas fa-swords": "fas fa-fist-raised",
    "fad fa-shirt": "fas fa-tshirt"
  }
}
~~~

Слева — полный набор исходных классов, справа — доступная на этой машине иконка.
Совпадение точное: если используются разные наборы классов, добавь отдельную замену.
Наличие Pro автоматически не определяется. Иконки, для которых нет замены, остаются исходными.

Замены применяются uiIcon, catalogueIcon и PHP InterfaceIcons при отображении.
Для произвольного исходного класса доступны resolveIcon и InterfaceIcons::resolve.
При сохранении справочников передавай исходный класс, а не результат этих функций:
локальная замена не должна попадать в БД или в общий icons.json.

После изменения локального файла пересобери интерфейс. Наблюдатель pnpm dev отслеживает этот файл.
При enabled: false либо отсутствии файла JS, PHP и значок расширения используют оригиналы.
Подстановка однократная: результат замены не проходит через другие замены.

### Перенос на основной форум

1. Выключи enabled в локальном файле либо собирай в копии, где этого файла нет.
2. Выполни pnpm build: это убирает замены из JS и возвращает оригинальный значок в composer.json.
3. Перенеси основную сборку и файлы пакета, без icons.local.json.

Само исключение файла из архива не очищает уже собранный JS. Не переноси локальную сборку
с включёнными заменами на основной форум. При изменении значка пакета обнови метаданные
установленного Composer-пакета и кэш Flarum, как описано выше.

### Проверка переключения режимов

Из корня новой версии: node tests/check-local-icons.cjs.
Нужны установленные JS-зависимости и запущенный Docker-сервис forum.
Необязательный первый аргумент — полный путь к Docker, если его нет в PATH.

Проверка временно переключает локальные настройки, собирает каждый режим и проверяет
реальный JS, PHP и значок Composer. В конце восстанавливает исходный локальный файл
и пересобирает интерфейс. Рабочая БД и старое расширение не затрагиваются.
