# Назначение конкретного предмета и защита брони

Согласовано 4 октября 2026 года. Тип предмета отвечает за название, описание, иконку и предел экипировки. Назначение оружия/брони теперь задаётся у конкретного предмета.

## Поля предмета

| Поле | Назначение |
| --- | --- |
| is_melee_weapon | Оружие ближнего боя |
| is_ranged_weapon | Дальнобойное/метательное оружие |
| is_magic_weapon | Магическое оружие |
| is_armor | Броня |
| ignored_damage_units | Величина игнорируемого урона брони |
| is_magical | Магический предмет — отдельный признак для подключения эффектов |

Все четыре назначения независимы и доступны при любом типе предмета. Магические свойства сами по себе не создают атаку от Магии.

Защита задаётся отдельно от урона, в том числе у немагической брони. В редакторе поле видно только при is_armor. При снятии галочки число сохраняется, чтобы переключение не теряло введённые данные. Применять его в расчёте можно только у экипированного предмета с is_armor.

Значение хранится в числовых единицах урона, как damage_units. Например, двойной Средний — 18. Ввод обеих величин использует один DamageEditor; параметр field выбирает редактируемое поле, label задаёт заголовок. Урон и защита не перезаписывают друг друга.

## Граница этого этапа

Реализованы редактор, сохранение через существующий API и получение полей в снимке через определение предмета. Построение доступных атак, учёт защиты брони в итоговом расчёте и подключения эффектов будут следующей частью. Сам тип и признаки предмета не подменяют требования владения оружием.

Для эффекта в будущем сохраняем определение в общем справочнике, а значение — в подключении к перку/магическому предмету. Влияние эффектов на характеристики пока требует ответа пользователя; этот документ не задаёт его автоматически.

## Проверки

Сценарии API проверяют сочетание всех назначений у предмета типа «Одежда», независимость от is_magical, защиту немагической брони, повторное сохранение, неправильные значения и отказ от устаревшего is_weapon у типа.

Клиентская проверка использует собранный редактор: несколько изменений до redraw, появление и скрытие защиты, сохранение скрытого значения, независимость урона и защиты. Снимки браузера не заменяются этими проверками.
Обновление следующего этапа: эффекты и защита брони подключены через CharacterCalculationBuilder; см. [эффекты](10-effects.md). Снимок состояния по-прежнему хранит приобретённые уровни и сам не рассчитывает бонусы.


Привязки владений и автоматический сбор атак: [11-available-attacks.md](11-available-attacks.md).

## Цена и стопки

base_price — цена одного предмета в золотых, с точностью до 0,001. В редакторе и JSON
дробная часть сохраняется. На карточке выводится целая часть общей стоимости стопки:
сначала base_price × quantity, затем отбрасывание дробной части. Например, 0,2 × 6 = 1,2 → 1.
Таблица справочника показывает целую часть цены одного предмета; точная цена доступна в редакторе.
Общий вывод — js/src/common/presentation.ts (itemStackPrice), все карточки используют ItemCard.
Миграция 2026_10_10_000001_fractional_item_prices переводит колонку в DECIMAL(19,3), сохраняя прежние цены.
