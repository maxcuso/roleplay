# Страница ролевой на форуме

Адрес Docker-копии: <http://localhost:8081/role>. В боковом меню списка тем добавлена
ссылка «Ролевая». Старый форум на 8080 не переключался.

## Источники и сборка

Текст остаётся обычным HTML, без Markdown-парсера и без преобразования в JSX.

| Файл | Назначение |
| --- | --- |
| `preview/role/index.html` | Единственный исходник текста и разметки |
| `preview/role/style.css` | Единственный исходник оформления компонентов |
| `preview/role/content.js` | Подписи главных вкладок; примеры используются только стендом |
| `preview/role/assets/` | Готовые картинки и шрифты |
| `resources/guide/page.js` | Общая логика вкладок, якорей, спойлеров и поворотов Badge |
| `resources/guide/forum.css` | Отступы под шапку Flarum и прочие особенности оболочки |
| `js/src/forum/guide/GuidePage.tsx` | Маршрут, загрузка текста, форумная тема и настоящий мастер |
| `js/scripts/build-guide.cjs` | Выбор содержимого из макета и изоляция стилей |
| `src/Guide/` | Чтение страницы и выдача только её иллюстраций и шрифтов |

`resources/guide/content.html` и `style.less` — результаты сборки; вручную не редактируются.
CSS получает префикс `.RpGuide`, имена шрифтов — `Guide`, поэтому правила страницы не
оформляют кнопки, заметки и заголовки в других разделах. Значения CSS передаются через
Less без вычисления `min()`, `calc()` и дробных соотношений.

Из `packages/roleplay-new/js`:

```text
npm run typecheck
npm run build
```

Из корня `C:\Forum\Flarum`:

```text
docker compose -f compose.roleplay-test.yaml up -d
docker compose -f compose.roleplay-test.yaml exec -T --user www-data forum php flarum cache:clear
```

В режиме `npm run dev` изменения HTML и CSS тоже запускают сборку. Стенд на 4173
по-прежнему работает отдельно и не нужен форуму. Для разработки используются отдельные
зависимости нового пакета, без общей папки node_modules со старым расширением.

## Поведение и границы переноса

- Сохранены три главные вкладки, боковые оглавления, вложенные вкладки характеристик
  и организаций, начальные состояния спойлеров, иллюстрации и шрифты.
  Выбор верхней вкладки мышью или клавиатурой возвращает к началу раздела `#guides`
  с учётом шапки форума. Прокрутка плавная; при уменьшенной анимации — мгновенная.
  Вложенные вкладки характеристик и организаций не возвращают к началу страницы.
- HTML страницы загружается через `GET /api/roleplay/guide`; из базы читаются
  иконки характеристик, шкалы развития с формулировками, три примера перков, перки уровней навыков и расовые наборы. Остальные тексты и таблицы
  пока остаются исходником макета. Полное подключение справочников — отдельный этап.
- В блоке `data-roleplay-block="perk-examples"` используется общий `PerkCard` в режиме
  `expanded`, с теми же размерами из `resources/cards.css`, что в мастере и профиле.
  API выбирает до трёх включённых перков по `sort_order`, затем ID. Название, описание,
  изображение и редкость обновляются при следующем открытии или обновлении страницы.
  Выключенные записи не показываются. Источник выдачи не придумывается; если перков нет,
  вместо заглушек выводится сообщение. Стенд на 4173 сохраняет свои статичные примеры.
- `data-attribute-skills="physiology"` (и три остальных характеристики) — места целых
  списков навыков, а `data-attribute-skill-list` — их краткие перечни в Facts. Число навыков,
  названия, описания и принадлежность приходят из базы; в HTML отдельных навыков нет.
  Включённые записи идут по `sort_order`, затем ID. Добавление, выключение и перенос
  навыка в справочнике отражаются при следующем открытии или обновлении страницы.
  Шаги чередуют стороны внутри каждой характеристики; на телефоне описание всегда первое.
  Используются прежние Step, Skill, Grid и общая карточка перка, без отдельного стиля.
- `data-skill-perks="unarmed-combat"` и `data-race-perks="human"` создаются вместе с
  блоками навыков и рас. `GuideCatalog` читает привязки по ID
  в одной согласованной версии каталогов. `GuidePerkCards.tsx` вставляет общий `PerkCard`,
  а `sourceLabel` оформляет источник так же, как в мастере и профиле. Название не является ключом.
  У навыка уровень расположен рядом в `Badge--level` внутри `Step--perk`. Порядок колонок
  исходных шагов сохранён, на телефоне сначала идёт навык, затем его перки.
  Фиксированные расовые перки отделены от вариантов на выбор; количество выбираемых берётся из базы.
  Неизвестная раса, пустой раздел навыков или отсутствующая привязка показывают сообщение,
  а не прежний текст макета. Публичный ответ не содержит числовых эффектов и полных настроек создания.
- `data-races` — единственное место списка рас в HTML. `GuideRaces.tsx` создаёт все
  включённые расы по порядку справочника (`sort_order`, затем ID). Название, описание,
  цитата, изображение, продолжительность жизни, рост, черты и цвет берутся из базы.
  Бонусы Facts строятся из `fixed_bonuses` и расовых выборов; они используют `paper-highlight`.
  Цвет задаётся существующим `data-accent`: Физиология — `ember`, Ловкость — `air`,
  Магия — `violet`, Харизма — `gold`, выбор — `water`.
  Сохранены Step--race с цитатой и портретом, прежняя рамка, тень и выступ изображения,
  Facts--wide-third и общие карточки перков. Пустое изображение заменяется значком
  в той же рамке, пустые справочные значения — тире. Пустой список показывает сообщение.
  Дополнительного импорта или записи данных при открытии страницы нет.
- У `.Badge` явно сброшены фон, рамка и тень штатного компонента Flarum: остаётся только
  вращаемая текстура круга. Другие значки форума этот сброс не затрагивает.
- Шкалы `data-attribute-development="physiology"` (и остальные три характеристики)
  заполняются `GuideDevelopment.tsx` из действующих настроек развития. Описание самой
  характеристики остаётся в HTML, иконка — в справочнике характеристик. События одного
  уровня объединяются в одну строку; степени урона выводятся безопасными `span.paper-highlight`.
  Формулировки хранятся в JSON `roleplay_development_config`: `rules[].description` и
  `initial_description`. Миграция `2026_10_22_000001_development_descriptions` переносит
  прежние формулировки без изменения баланса, постоянных ключей и выданных выборов.
  В админке «Развитие» текст можно изменить при редактировании правила. Подстановки
  `{damage}`, `{circle}`, `{value}`, `{skill_levels}`, `{proficiency_choices}`, `{proficiency}`
  сохраняют связь текста с числами и названиями; доступные варианты показаны в редакторе.
  Начальная строка использует `{stamina_max}` / `{mana_max}` из настроек ресурсов.
  HTML из этих полей не исполняется. На отдельном стенде без базы остаётся поясняющая заглушка.
- Требования к II и III уровням в заметке «Навыки» (`data-skill-minimum`)
  и строки таблицы «Стоимость повышения» (`data-experience-costs`) читаются из
  `skill_minimums`, `experience_costs` и `maximum_level` тех же настроек развития.
  Диапазоны таблицы строятся по действующим порогам, без фиксированных границ в HTML.
  Уровни у карточек навыков выводятся римскими цифрами I–III; числовые значения в базе сохраняются.
- Таблица «Ранги» Гильдии Квестпоста (`data-guild-ranks`) читает включённые записи
  справочника рангов по возрастанию номера. Сохранены три колонки: римский номер,
  еврейская буква с изоляцией направления и название. Описание доступно в подсказке
  строки. Пустой справочник показывает сообщение вместо прежних десяти строк.
  Данные рангов и назначения персонажам при открытии правил не меняются.
- Кнопка создания открывает существующий `CreationWizardModal`. Гостю открывается вход;
  пользователю без права создания показывается сообщение. Сама страница персонажей не создаёт.
- Тема следует за темой Flarum. Отдельные шапка, подвал, переключатель темы и автообновление
  стенда на форум не переносятся. Вымышленные анкеты галереи тоже остаются только на стенде.
- Обращение к читателю — на «вы». В заголовках окон используются «Создание…»,
  «Редактирование…» и другие названия действий; кнопки сохраняют форму команды.
  В завершающих предложениях блоков нет точки. Для данных справочников `guideText.ts`
  убирает только конечную точку при показе правил, сохраняя внутреннюю пунктуацию,
  сокращения, многоточия и исходные записи базы. Цитаты выводятся без изменений.
- Общий runtime связывает предлоги, короткие союзы и частицы со следующим словом
  обычным неразрывным пробелом U+00A0. Старые U+202F заменяются на U+00A0.
  Точки с запятой в отображаемом тексте заменяются запятыми. Это касается HTML и уже вставленных карточек справочников, включая текст
  через границы inline-выделений. Разные абзацы не соединяются; код, поля ввода,
  редактируемые области и адреса ссылок не меняются. Исходники и база сохраняют
  обычные пробелы. Для исключения отдельного блока предусмотрен `data-no-typography`.
- Заглушки скриншотов, недостающих гербов и интерактивной карты сохранены.
- При уходе со страницы снимаются обработчики прокрутки, якорей и наблюдатели.
- Маршрут `/role/media/{path}/file` выдаёт только изображения и шрифты внутри
  `preview/role/assets`. Суффикс нужен, чтобы nginx не перехватывал запросы `.png` и `.ttf`.
  Обход каталогов, PHP, настройки, исходники и `tests/.runtime` через него недоступны.

## Проверка

`tests/check-guide-forum.cjs` проверяет страницу гостем на действующем Docker-форуме:
главные вкладки, переход к закрытому спойлеру, вход по кнопке создания, мобильную ширину,
возврат через навигацию Flarum и доступность иллюстраций. Не отправляет формы и не меняет базу.

`tests/check-guide-perks-forum.cjs` проверяет все 11 навыков и 8 рас, уровни сбоку,
источники карточек, мобильный порядок и отсутствие квадратной подложки Badge.
Неполные связи проверяются подменой ответа только в отдельном браузере, без изменений базы.

`tests/check-guide-skills-forum.cjs` добавляет шесть навыков в тестовом ответе API,
переносит один между характеристиками, убирает другой и опустошает одну вкладку.
Проверяет автоматические перечни, принадлежность значков, чередование колонок,
мобильный порядок и безопасный вывод описаний. База при этом не изменяется.

`tests/check-guide-races-forum.cjs` сверяет все поля реальных рас, рамку и положение
портрета на телефоне. Подменой API добавляет три расы, удаляет одну, проверяет бонусы,
отсутствующие изображения и сведения, безопасный текст и полностью пустой список.

`tests/check-guide-development-forum.cjs` проверяет четыре шкалы и 53 правила,
сохранённые формулировки, выделение урона, мобильную ширину и живую подстановку
изменённых текста, порога и урона. Изменения ответа API ограничены тестовым браузером.
