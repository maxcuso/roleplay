# Шаг 2. Серверная основа справочников

> Документ описывает исходный шаг. Актуальная схема и подключённая админка описаны в [шаге 4](04-admin-catalogs.md). Первая миграция расширена до установки новой версии.

## План
Перенести проверенные поля пяти базовых справочников, транслитерацию и защиту версии. Создать чистую миграцию и отдельное начальное наполнение. Проверить сохранение на временных таблицах. Затем по очереди подключать административные редакторы.

## Архитектура
- Shared/FieldValues — проверки обычных полей: текст, число, переключатель, иконка.
- Shared/DefinitionSlug — перенесённая транслитерация. Ключ генерируется при создании; переименование его не меняет.
- Shared/CatalogRevision — согласованное чтение/изменение под блокировкой версии.
- Shared/DefinitionStore — таблицы, пагинация, запись, переключатель статуса. Не знает игровых особенностей.
- Attributes/AttributeCatalog — оформление характеристик.
- Races/RaceCatalog — имя, описание и возраст.
- MagicPaths/MagicPathCatalog — иконка и цвет.
- ItemTypes/ItemTypeCatalog — иконка, лимит экипировки и признак оружия.
- PerkSources/PerkSourceCatalog — зависимость названия/иконки и явные переопределения по характеристикам.
- SeedBaseCatalogs — явная операция начального наполнения из resources/defaults/base-catalogs.php.

Каждый справочник имеет list(), save() и toggle(). save() получает всю форму, ожидаемую версию и администратора. toggle() меняет только статус. Неизвестные поля формы запрещены; системный ключ из браузера не принимается.

API-маршруты и редакторы подключаем следующим шагом. Удаление подключаем вместе с проверкой использующих запись сущностей и внешними ключами.

## Таблицы первой миграции
Общее: id, name, slug, description, enabled, sort_order, created_at, updated_at. slug уникален; порядок поиска — sort_order и id.
- roleplay_catalog_state: одна техническая запись с id=1 и revision.
- roleplay_attributes: icon.
- roleplay_races: min_age, max_age.
- roleplay_magic_paths: icon, color.
- roleplay_item_types: icon, equipment_limit. Виды оружия и признак брони задаются у конкретных предметов.
- roleplay_perk_sources: icon, name_source, icon_source, attribute_icons.

Иконки не находятся в миграции. Тип предмета не имеет устаревшей category. Источник starting запрещён. Возраст и лимиты проверяются приложением и ограничениями БД.

## Что ещё подключим
Расовые фиксированные бонусы, группы выбора, перки и заклинания добавим вместе с Rules и справочниками способностей. Сейчас RaceCatalog сохраняет только основные сведения; он не выдаёт способности.

Начальные определения — минимальные: четыре характеристики с уже использовавшимися иконками. Это не заполнение всего игрового мира. Остальные данные добавляются редакторами или отдельным согласованным набором.

## Где менять
- Поля и ограничения конкретного справочника: его класс, метод validate().
- Иконки начальных характеристик: resources/defaults/base-catalogs.php. На работающем форуме — соответствующий редактор.
- Общие пределы длины: Shared/FieldValues.
- Формат списка и пагинацию: Shared/DefinitionStore.
- Правила транслитерации: Shared/DefinitionSlug.
- Структуру чистой БД: migrations/2026_10_02_000001_create_base_catalogs.php.

Инициализация только добавляет отсутствующие записи и не меняет существующие. Миграция применяется тестом к отдельным временным таблицам с уникальным префиксом; рабочие таблицы старого расширения не затрагиваются.
