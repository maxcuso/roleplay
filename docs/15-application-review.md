# Литературная тема и независимая проверка

После семи шагов мастера расширение создаёт тему от имени игрока, в теге из настроек, с шаблоном первого сообщения.
Техническая часть сразу получает статус «На проверке». Литературная часть сначала «В работе»:
игрок заполняет шаблон в своей теме и нажимает «На проверку» в профиле.
Ссылка на тему находится прямо в пояснении литературной части.
Изменение сообщений в теме само по себе не отправляет черновик на проверку.
После отправки кнопка меняется на «Отозвать»: владелец может вернуть литературную часть в «В работе»,
пока её не одобрил модератор. Техническая проверка при этом не меняется.

В настройках «Анкеты и проверка» выбираем дочерний тег «Анкеты» (`characters`) основного тега
«Ролевая» (`role`). При создании темы адаптер отправляет оба ID: родителя и дочернего тега.
ID не зашиты в коде и не требуют миграции; на другом форуме нужно выбрать его собственный тег в настройках.

На страницах `/t/role` и `/t/characters` кнопка «Создать персонажа» занимает место «Создать тему»
в боковой панели. В правой части шапки отдельной кнопки больше нет. У модераторов обычное создание
тем остаётся второй кнопкой. Для остальных пользователей оно скрыто только в этих двух тегах;
форумные права и возможность отправить обычный запрос создания темы не меняются.
Размещение описано в `js/src/forum/creation/addCreationButton.ts`: обработчик подключается после `flarum-tags`,
чтобы стандартная настройка кнопки тегом не перезаписывала кнопку персонажа.

Техническую часть модератор проверяет в профиле. При возврате обязательны замечания.
Пока техническая часть не одобрена, владелец может изменить весь стартовый выбор в общем мастере.
Последнее сохранение оставляет техническую часть на проверке. Подробности — [документ 19](19-technical-editing.md).

Литературное принятие определяется по двум условиям:
- тема закрыта;
- последнее видимое обычное сообщение от модератора/администратора содержит только плашку принятия.

Служебная запись о закрытии темы не считается обычным сообщением.
Цитата плашки, другая плашка или сообщение игрока не дают одобрения.

    [success title=Принято font=#1E2019 bg=#A9C7AA border=#A9C7AA][/success]

Литературной кнопки одобрения в профиле нет. Сервер разрешает владельцу отправку (`submit`) и отзыв (`withdraw`),
а одобрение продолжает определяться плашкой и закрытием темы. История проверки открывается кнопкой-иконкой
в отдельном компактном окне; она не разворачивает панель профиля.
Персонаж активируется, когда обе части одобрены. Их порядок не важен.

## Архитектура и места изменения

| Модуль | Назначение |
| --- | --- |
| ApplicationTopics / FlarumApplicationTopics | Создание темы через API Flarum с правами игрока; чтение состояния темы и последних сообщений |
| LiteratureAcceptance | Проверка самостоятельной BBCode-плашки, её заголовка и цветов |
| LiteratureSynchronizer | Запись наблюдённого решения и активация; повторное одинаковое наблюдение ничего не меняет |
| SynchronizeLiteratureEvent | Реакция на публикацию/изменение/скрытие постов и закрытие/открытие темы |
| CharacterReview | Технические решения и проверка литературного состояния перед активацией |
| CharacterIdentity | Исправление личных данных |
| ApplicationPostPolicy | Редактирование первого сообщения своей создаваемой анкеты; сохраняет ограничения видимости и закрытой темы |
| CharacterOperation | Общие права, версии, транзакция, UUID повтора и журнал |
| ReviewPanel / ReviewDecisionModal | Технические действия, статусы и замечания |
| ApplicationSettingsPanel | Тег, заголовок и литературный шаблон в админке |

События синхронизируются после завершения записи форума. Чтение профиля не записывает решение.
До активации изменение текста, открытие/скрытие темы снимает наблюдённое литературное одобрение.
У активного персонажа пока сохраняется историческое одобрение — изменение этого поведения требует отдельного решения.
Администраторская перепривязка темы сохраняет ранее выданное одобрение, как было согласовано.

## API и проверки

GET /roleplay/characters/ID возвращает анкету, состояния и доступные действия.
POST /roleplay/characters/ID/review принимает part=mechanics и approve/request_changes/submit,
либо part=literature и submit/withdraw.
PUT /roleplay/characters/ID/identity принимает только имя, фамилию и возраст.
GET/PUT /roleplay/admin/application меняет настройки литературной темы, сохраняя прочие настройки старта.

Команды требуют operation_key, revision и catalog_revision. Права повторно проверяются сервером.
Решение, версия и событие сохраняются атомарно; точный повтор не дублируется.

Сценарии tests/check-base-catalogs.php проверяют создание темы, откат, обе проверки, права, исправления,
плашку, повторное наблюдение, активацию и настройки. Они используют временные таблицы, не рабочие анкеты.
Контракт реального адаптера темы проверяется без отправки настоящей темы.
Браузерная проверка рабочего форума пока не выполнялась.
