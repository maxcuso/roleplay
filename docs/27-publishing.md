## Подготовка репозитория

Создай отдельный публичный репозиторий для содержимого этой папки расширения. `composer.json` должен находиться в корне репозитория. Весь форум для этого публиковать не нужно.

`.gitignore` исключает локальные зависимости, сгенерированные типы `.flarum-typings`, настройки замен иконок и `tests/.runtime`. В последней папке могут находиться копии базы и личные данные тестовой установки. Готовая папка `js/dist` включается в Git: без неё установленный пакет не загрузит интерфейс. Зависимости фиксируются только в `js/package-lock.json`.

Проверь состав выбранных файлов перед первым коммитом. `.gitattributes` задаёт аналогичные исключения для Git-архива, а `archive.exclude` в Composer — для `composer archive`. Эти правила не удаляют уже опубликованные файлы из истории Git.

## Сборка релиза

Для релизной сборки отключите локальные замены в `resources/presentation/icons.local.json` (`enabled: false`) или временно вынесите этот файл за пределы пакета. Отдельная папка проекта не требуется.

Из папки `js`:

```text
npm ci
npm run types:sync -- /forum/vendor/flarum/core/js/dist-typings
npm run typecheck
npm run build
```

Обычная локальная сборка использует включённые замены иконок. Их таблица встраивается в JavaScript; исключить только исходный JSON недостаточно. Чистая сборка также возвращает оригинальную иконку расширения в `composer.json`.

После сборки в корне пакета:

```text
composer validate --strict
```

Добавь готовый `js/dist` в коммит релиза вместе с исходниками. Номер версии вручную в `composer.json` не добавляй: Composer получает его из Git-тега.

## Публикация

1. Создай или проверь аккаунты GitHub, Packagist и Floxum.
2. Загрузи репозиторий на GitHub, затем выпусти тег согласованной версии, например `v0.1.0`.
3. На Packagist выбери **Submit** и укажи публичный URL репозитория. Имя пакета и префикс автора должны быть доступны твоему аккаунту.
4. Настрой автоматическое обновление Packagist при публикации новых тегов.
5. Дождись появления версии на Floxum, войди с почтой `charomax11@gmail.com` и открой страницу расширения для запуска аудита.

Аудит относится к опубликованной версии. Для проверки исправлений выпусти следующий тег; старые теги не переписывай. Если Floxum ещё не получил обновление, проверь версию на Packagist и воспользуйся его кнопкой **Update**.

Оценка служит ориентиром: исправления выбираем по содержанию замечаний, а не только по баллу.
