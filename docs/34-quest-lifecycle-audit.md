# Проверка пути от карточки квеста до эпизода

Дата: 28 октября 2026 года. Локальная тестовая копия QuestPost.

По просьбе пользователя сначала проверена существующая цепочка. Следующий шаг —
согласование дизайна окна завершения и наград, затем его реализация.
Игровая логика при этой проверке не изменялась.

## Проверенный сквозной сценарий

Новый сценарий `tests/check-quest-lifecycle.php` использует штатную публикацию,
регистрацию, запуск отдельного события и модераторскую. Он проверяет:

- Публикация полного BB-кода создаёт набор в квест с одним ведущим и сохраняет
  короткую ссылку на карточку в исходном сообщении
- Запись через существующий API сохраняет именно выбранного активного персонажа,
  а достижение минимума назначает запуск
- Запуск создаёт связанную тему от имени ведущего с описанием и упоминанием участника
- Карточка показывает действующий эпизод, набор закрывается, привязка персонажа сохраняется
- Ведущий видит эпизод и выбранного персонажа в «Моих эпизодах»
- Повторный запуск не создаёт ещё одну тему
- Штатное закрытие темы завершает квест и перемещает его в архив ведущего
- Заявленные в карточке опыт и золото при запуске и ручном закрытии не начисляются

Сценарий прошёл. Все временные темы, сообщения, персонажи, события и изменения
настроек откатились. После отката отдельно сверены количества событий, тем,
сообщений, персонажей и игровых операций. Рабочая очередь запуска не вызывалась.

## Дополнительные проверки

Повторно выполнены, прошли:

- `check-quest-integration.php`: один/несколько персонажей, запрет чужого,
  непринятого или недоступного персонажа, выход и исключение без оставшейся привязки,
  обычные форумные события без персонажа
- `check-quest-client.cjs`: открытие выбора не занимает место, один персонаж
  подставляется автоматически, несколько требуют выбора
- `check-events-actions.php`: права, дубли, лимиты, расписание и выход
- `check-events-drafts.php`: актуальные текст и теги черновика, авторство ведущего,
  сохранение причины ошибки запуска, закрытие без наград
- `check-events-management.php`: права редактора, версии формы, смена ведущего,
  ограничения после старта и сохранение опубликованной темы при удалении карточки

Это проверка серверной цепочки и клиентских обработчиков на временных данных.
Прохождение опубликованного квеста вручную в браузере в этой проверке не выполнялось.

## Особенности, которые нужно учесть дальше

1. Унаследованный лимит — два набора/действующих события на аккаунт суммарно,
   включая обычные форумные события. Это не лимит на каждого персонажа.
   Изменение этого правила пока не согласовано.
2. Редактор допускает снятие ведущего (`leaderId = null`), после чего запуск
   останавливается с сохранённой причиной. Это противоречит согласованному
   правилу одного обязательного ведущего. При доработке нужно запретить пустое
   назначение; само назначение не должно добавлять право выдавать награды.
3. В первом сообщении эпизода перечислены аккаунты через упоминания. Конкретные
   персонажи доступны в карточке и модераторской. В будущем окне наград нужно
   брать сохранённые привязки персонажей, а не текущий выбор в профиле.
4. Если используется черновик, тема получает его теги. Без черновика специальный
   тег эпизодов автоматически не назначается: создаётся обычная тема.
5. Четыре категории историй и связь «продолжение» ещё не добавлены в формат данных.
6. Награды в карточке сейчас являются объявлением условий. BB-кода завершения,
   расчёта бонусов и отдельного исправления награды пока нет — это следующий блок.

До согласования дизайна исправления этих особенностей и новый рабочий интерфейс
не вносятся. Макет окна предназначен только для обсуждения, без реальных начислений.

## Согласованный дизайн окна завершения

Пользователь выбрал первый вариант: список персонажей слева, редактор награды
справа. Раскрывающиеся строки не используем. На узком экране части располагаются
последовательно. Отдельный предпросмотр исключён по просьбе пользователя.

- В шапке название эпизода и количество получателей
- У выбранного персонажа базовый опыт и золото, ниже источники процентных бонусов
  и итоговый опыт с округлением вниз
- Предметы, перки и заклинания добавляются отдельными компактными строками
- Для выбора предметов обязателен поиск по названию. Тот же общий поиск
  предусматривается для перков и заклинаний. В рабочем интерфейсе — серверный
  поиск и порционная загрузка, без загрузки целого справочника
- Уже известное знание помечается как пропускаемое, без отмены остальных наград
- Есть добавление другого активного персонажа вне записи через карточку
- Будущие награды видны прямо в форме, отдельного предпросмотра нет
- Последняя кнопка — «Вставить код», а не немедленная выдача
- Начисление и закрытие темы происходят только при публикации сообщения

Данные, названия и проценты в макете являются демонстрационными.
Существующие редакторы и штатные элементы Flarum будут переиспользованы при
реализации согласованной структуры. Сам макет к серверу не подключён.

публикация, награды и закрытие. Актуальное состояние — в
[описании завершения эпизода](35-episode-completion-form.md).
