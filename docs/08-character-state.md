# Состояние персонажа: перенос и подготовка расчётов

Реализованы хранение характеристик, уровней навыков и владений, чтение полученных сущностей и сборка общего снимка. Это основа для мастера, профиля и развития. Операции создания, повышения, выдачи и списания, а также новые страницы пока не подключены.

## Что взяли из прежнего расширения

| Прежний код | Сохранённый подход | Что изменили |
| --- | --- | --- |
| Character/CreateCharacter.php | Отдельные base_value и racial_bonus, уровень навыка, бинарное владение | Перенесли структуру хранения; черновики, экономика и операции требуют своего этапа |
| CharacterController.php | Выборка принадлежащих персонажу записей | Чтение вынесено в отдельный класс без HTML и формул |
| CharacterCards.php | Связь выдачи с определением сущности | Определения готовят существующие каталоги; источник относится к выдаче; дубли перка отклоняются |
| CharacterStatCalculator.php | Раздельные расовые прибавки и учёт экземпляров экипировки | Чтение отделено от уже реализованного калькулятора; старые формулы и таблицы иконок не копировались |

Перенесена нужная часть работающей модели. Старые файлы не изменены. Специальные поля и обходные решения прежней версии не становятся требованиями новой автоматически.

## Архитектура и места редактирования

~~~text
будущий сценарий/API — проверка прав
    |
CharacterStateReader — чтение одной версии
    |          |
    |          CatalogRegistry / DefinitionStore — существующие определения
    |
CharacterSnapshotBuilder — проверка и подготовка
    |
CharacterSnapshot — неизменяемые данные без SQL
    |
CharacterCalculator — расчёт по переданным данным
~~~

| Файл | Что редактировать |
| --- | --- |
| src/Character/State/CharacterStateReader.php | Какие принадлежащие персонажу записи и связанные определения загружать |
| src/Character/State/CharacterSnapshotBuilder.php | Проверки состояния и структуру подготовленных сущностей |
| src/Character/State/CharacterSnapshot.php | Общий формат снимка и ввод для базового расчёта |
| src/Rules/CharacterCalculator.php | Производные параметры; формулы задаются в resources/rules/stats.php |
| src/Catalog/Shared/CatalogUsage.php | Запрет удаления определений, используемых персонажем |

Reader загружает определения пакетами, а не отдельно для каждой вещи. SQL-типы и JSON нормализуются существующими каталогами через definitionsFor(). Формулы, иконки и справочники в классы чтения не копируются.

## Хранение

Добавлены три таблицы; базовая миграция теперь создаёт 19 таблиц. Пакет ещё не установлен, поэтому меняем исходную структуру без очередной миграции. Рабочие таблицы старого расширения не затронуты.

| Таблица | Основные поля |
| --- | --- |
| roleplay_character_attributes | character_id, attribute_id, base_value, racial_bonus |
| roleplay_character_skills | character_id, skill_id, level |
| roleplay_character_weapon_proficiencies | character_id, proficiency_id |

У всех трёх записей есть created_at и updated_at. Одна характеристика, навык или владение встречается у персонажа один раз. Внешние ключи и проверка использования защищают определения от удаления.

base_value — записанный базовый уровень; racial_bonus — записанная при создании расовая прибавка, включая выбранный вариант. Снимок складывает их, но не читает текущие rules расы для повторного начисления. Правка расы не меняет записанные прибавки; будущая операция создания должна сохранить результат проверенного стартового выбора в эти поля.

База и итог не могут быть меньше 1; максимум проверяется по DevelopmentRules (сейчас 25). Навык хранит текущий уровень I–III. Владение не имеет уровня.

Перки, заклинания и вещи используют существующие таблицы состояния. Добавлена уникальность character_id + perk_id: у полученного перка один источник. Повторное получение через навык не должно создавать вторую выдачу — это обязанность будущей операции обучения. Источник и source_context уже полученного перка сохраняются.

Экипированная вещь — отдельный экземпляр с quantity = 1. Экипировка является выборкой из инвентаря. Вес считается только по общему инвентарю, поэтому вещь не учитывается дважды. Отсутствующий вес или null означает 0.

Текущие max_stack и equipment_limit не применяются задним числом при чтении. Их проверят операции имущества. Изменение справочника само по себе не снимает вещь и не разделяет стопку.

## Состав снимка

- Заголовок персонажа и отдельные версии персонажа/справочников.
- Характеристики: база, записанная расовая прибавка, итог, текущие название и иконка.
- Навыки с текущими уровнями и изученные владения.
- Перки: определение и единственный источник конкретной выдачи.
- Изученные заклинания вместе с текущим определением пути.
- Экземпляры инвентаря с количеством, весом и флагом экипировки; выборка экипировки.
- Список отсутствующих характеристик.

Отключённые определения остаются у уже получившего их персонажа. Нет фильтра enabled: отключение запрещает новые выборы, а не чтение существующего состояния.

Builder отклоняет чужую запись, дубли сущностей и экземпляров, отсутствующее определение и некорректные уровни. Неполный снимок сообщает об отсутствующих характеристиках, а базовый расчёт запрещается. Первый уровень не подставляется молча.

## Расчёт и границы этапа

~~~php
$reader = new CharacterStateReader($db);
$builder = new CharacterSnapshotBuilder($reader, DevelopmentRules::defaults());
$snapshot = $builder->build($characterId);

$calculator = new CharacterCalculator(StatRules::defaults());
$baseline = $calculator->calculate(...$snapshot->baselineInput());
~~~

baselineInput() готовит записанные уровни, весь инвентарь и уровни навыков. Это позволяет проверить базовые максимумы ресурсов, защиту от характеристики, вес и прибавки к проверкам навыков.

Сам снимок не является итоговым расчётом: в JSON поле pending_calculation содержит effects и attack_modes. Полный результат готовит CharacterCalculationBuilder, включая эффекты и доступные атаки; см. [11-available-attacks.md](11-available-attacks.md). Текст свойства предмета не разбирается как формула.

Иконки характеристик берутся из справочника; навыки и владения наследуют их через существующее представление. Изменение иконки не требует миграции. Снимок не форматирует ступени урона и римские цифры.

## Права и согласованность

Reader — внутренний сервис, не маршрут API. Вызывающий сценарий обязан проверить видимость и право доступа. Сериализация снимка описывает внутренний формат, а не утверждённый публичный ответ профиля.

Чтение идёт в транзакции: общая блокировка версии справочников, затем заголовка персонажа. Будущие операции записи должны соблюдать тот же порядок и блокировать персонажа перед изменением связанных строк. Это предотвращает смешение старого заголовка с новой экипировкой/выдачами. Версия справочника не заменяет версию персонажа.

Чтение не обновляет строки и версии. Запись, проверка ожидаемой версии, история и защита повторного запроса остаются у соответствующих операций.

Сценарии подключены из tests/character-state-scenarios.php. Интеграционный тест создаёт отдельные временные таблицы, проверяет чтение, ограничения, запреты удаления, откат и повторную установку схемы. Удаляются только таблицы с уникальным проверенным префиксом теста. Администратор не создаётся.

Проверяются правка расы после записи прибавки, отключённые полученные сущности, разные источники одного перка у двух персонажей, чужой инвентарь, вес без повторов, неполное состояние, повреждённые ссылки и дубли, неизменность версий при чтении.
Обновление следующего этапа: эффекты и защита брони подключены через CharacterCalculationBuilder; см. [эффекты](10-effects.md). Снимок состояния по-прежнему хранит приобретённые уровни и сам не рассчитывает бонусы.
