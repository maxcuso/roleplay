# Импорт и экспорт справочников

Кнопки над таблицей открывают общие окна импорта и экспорта. Персонажи не входят в перенос.
Экспорт: раздел целиком, все результаты текущих фильтров или все справочники и сущности.
Связанные определения включаются автоматически, в том числе весь пул заклинаний пути расового выбора.

## Файл

```json
{
  "format": "roleplay-catalogs",
  "version": 1,
  "catalogs": {
    "item-types": [{"key": "clothes", "name": "Одежда", "equipment_limit": 5}],
    "items": [{"key": "cloak", "name": "Плащ", "item_type_key": "clothes"}]
  }
}
```

Разделы: `attributes`, `races`, `paths`, `item-types`, `sources`, `skills`, `proficiencies`,
`perks`, `spells`, `items`, `ranks`. Можно оставить только нужные разделы и записи.
Недостающая в файле зависимость допустима, если её ключ уже существует на форуме.

`key` — существующий `slug`: стабильная идентичность записи, не её название.
Переименовывай `name`, сохраняя `key`, если хочешь обновить ту же запись.
Новый ключ создаёт отдельную запись даже при одинаковом названии; предпросмотр предупреждает об этом.
В файле нет ID базы, времён создания/изменения и данных персонажей.

Поля совпадают с полями редактора, кроме связей:

- `attribute_key`, `skill_key`, `magic_path_key`, `item_type_key` вместо соответствующих `*_id`.
- `melee_proficiency_key`, `ranged_proficiency_key`, `magic_proficiency_key` у оружия.
- `levels[].perk_key` у уровней навыка; `effects[].attribute_key` / `effects[].skill_key` у встроенных эффектов.
- В расовых `rules`: `fixed_perk_keys`, `perk_choice_keys`, `fixed_spell_keys`,
  `spell_choice_keys`, `spell_choice_path_keys`, `proficiency_choice_keys` вместо `*_ids`.
- `fixed_bonuses`, `choice_attributes` и `attribute_icons` уже используют ключи характеристик.

Все остальные поля, включая свойства предметов, величины эффектов, флаги, иконки и сортировку,
переносятся как в редакторе. Отсутствующее необязательное поле получает обычное значение по умолчанию:
обновление является заменой редактируемого определения, а не частичным исправлением отдельных полей.
Для массовой правки удобнее экспортировать, отредактировать полученный файл и импортировать обратно.

Поле перка `image` принимает прямую внешнюю HTTP(S)-ссылку или путь `/assets/...`.
Файл изображения не скачивается на сервер. Локальные изображения для другого форума перенеси отдельно.
JSON — без комментариев; размер до 10 МБ, до 5000 записей. BOM из редакторов Windows допускается.

## Проверка и применение

По умолчанию существующие ключи пропускаются. Режим «Обновить существующие» заменяет их поля,
сохраняя локальные ID и выдачи персонажам. Он распространяется и на зависимости внутри файла.
Ничего не удаляется. Изменения определений могут влиять на персонажей так же, как обычная правка в админке.

«Проверить файл» возвращает список действий и ошибок без сохранения данных.
Смена файла или режима сбрасывает отчёт; изменение справочников после проверки требует нового отчёта.
Применение перепроверяет пакет и выполняется целиком. Ошибка откатывает все записи и общую версию.

Внутри транзакции сначала резервируются минимальные определения, затем выполняются обычные сохранения.
Это разрешает цикл «навык → перк → эффект → навык» без отключения внешних ключей.
Предпросмотр откатывает эти записи; в числовых ID могут остаться пропуски после отката автоинкремента.
Для переноса ID не используются.

Снимок может восстановить привязки выключенных эффектов: выключение не удаляет существующие привязки.
Редактор по-прежнему запрещает вручную добавлять выключенный эффект. Прочие ограничения сохранения,
включая запрет менять поведение используемого эффекта, действуют и при импорте.

## Где менять код

- `src/Transfer/CatalogJsonTransfer.php` — чтение, зависимости, пакетная транзакция и отчёт.
- `src/Transfer/CatalogJsonReferences.php` — карта связей и преобразование ключей/ID.
  При добавлении новой связи меняй эту карту; новая миграция для механизма переноса не нужна.
- `src/Api/CatalogJsonController.php` — административные запросы импорта/экспорта.
- `js/src/admin/catalog/CatalogTransferState.ts` — загрузка файла, режим, проверка и применение.
- `js/src/admin/catalog/components/CatalogTransferModal.tsx` — общее окно.
- `resources/admin.css`, селекторы `RpTransfer-*` — оформление и прокрутка.
- `resources/presentation/icons.json` — все значки кнопок и окон.

Доступ только администраторам. Права модераторской выдачи не дают доступ к переносу.
Старый `CatalogTransfer` остаётся отдельным разовым сценарием для пустой схемы.

Проверки: `tests/check-catalog-json.php` (временные таблицы, сквозной перенос и откат)
и `tests/check-catalog-json-client.cjs` (граница проверки/применения, смена режима и открытие окон).

## Эффекты внутри владельца

```json
{
  "key": "zapas-many",
  "name": "Запас маны",
  "effects": [{"mechanic": "stat", "stat": "mana_max", "operation": "add", "value": 10}]
}
```

Список `effects` входит в перк или магический предмет, отдельного раздела нет. Числовой эффект не требует имени и описания. Для `mechanic: "text"` укажи `name`, без `value`. Необязательные `condition`, `condition_text`, `scope`, `icon`, `description` соответствуют редактору. У целей характеристик и навыков используются системные ключи, зависимости включаются в экспорт автоматически.

Старые файлы версии 1 с отдельным разделом `effects` и `effect_key` поддерживаются: определения из того же файла копируются внутрь владельцев. Один старый раздел эффектов без перков/предметов больше не импортируется. Новый экспорт всегда использует встроенный формат.
