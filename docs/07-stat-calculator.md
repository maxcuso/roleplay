# Калькулятор параметров персонажа

Реализован расчёт в памяти для будущих мастера создания, профиля и предпросмотра прокачки. Он не читает базу, не выдаёт способности, не расходует ресурсы и не меняет персонажа.

## Чем отличался предыдущий вариант

Старый CharacterStatCalculator загружал характеристики, перки, экипировку и эффекты прямо из базы. В одном классе были чтение SQL, применение бонусов, расчёт, форматирование, подписи и часть иконок.

Последовательность была такой:

1. Базовая характеристика + расовый бонус + бонусы характеристике.
2. Применение формулы из таблицы roleplay_stats.
3. Прибавление эффектов, направленных на производный параметр.
4. Форматирование итогового значения и слагаемых.

Мана и выносливость уже использовали правильную формулу: 8 + 2 × уровень, то есть 10 на первом уровне. Начальные пороги ближнего урона в старом наполнении были 1/2/7/12. Игнорирование было зашито в самом классе: 5 → 1, 14 → 3, 18 → 9; двойного Среднего не было.

Калькулятор не читал damage_units самого предмета. Эффекты разных экипированных экземпляров складывались в общий параметр урона. Поэтому отдельного расчёта двух оружий с выбором максимума не было.

Старые файлы оставлены без изменений. Новый вариант сохраняет числовое сложение, источники и условие безоружной атаки, но применяет согласованные пороги и разделяет расчёт оружий.

## Архитектура

| Файл | Ответственность |
| --- | --- |
| resources/rules/stats.php | Формулы ресурсов и грузоподъёмности, пороги урона/защиты, способы атаки и круги магии |
| src/Rules/StatRules.php | Проверяет конфигурацию, читает базовые значения и правила |
| src/Rules/CharacterCalculator.php | Общая точка расчёта: параметры, атаки, максимум, вес и бонусы проверок навыков |
| src/Rules/AttackCalculator.php | Отдельная атака, максимум по виду урона, уменьшение входящего урона |
| src/Rules/CalculatedValue.php | Итог и слагаемые с источниками; безопасное числовое сложение |
| src/Rules/StatModifier.php | Подготовленная прибавка, её цель и область применения |
| tests/check-stat-calculator.php | Сценарии и границы расчётов |

Максимум характеристики и максимум навыка берутся из уже существующего DevelopmentRules. В новой конфигурации эти пределы повторно не задаются.

Для линейной формулы используются offset + factor × уровень. Например, для маны offset = 8 и factor = 2. У пороговой формулы берётся значение последнего достигнутого уровня; предыдущие ступени не суммируются.

Иконки, цвета, имена конкретных перков и ID из базы в формулах не хранятся. Название характеристики приходит из её определения.

## Входные данные

Калькулятор принимает подготовленный снимок:

- attributes: системный ключ характеристики → её название и итоговый уровень;
- modifiers: список объектов StatModifier;
- attacks: список доступных вариантов атак;
- inventory: весь переносимый инвентарь, включая экипировку;
- skillLevels: ID или ключ навыка → текущий уровень.

Калькулятор принимает итоговые уровни характеристик, включая расовые и другие применимые прибавки. CharacterSnapshotBuilder складывает записанные базовые уровни и расовые прибавки; CharacterCalculationBuilder применяет числовые эффекты. Отдельные бонусы характеристикам здесь повторно не добавляются.

CharacterSnapshotBuilder проверяет принадлежность вещей, CharacterAttackBuilder собирает атаки по экипировке и владениям. CharacterEffectResolver устраняет повтор одной выдачи перка из нескольких источников. Калькулятор не угадывает доступность из названия оружия или текста перка.

## Числовые бонусы

У StatModifier есть:

| Поле | Значение |
| --- | --- |
| target | Целевой параметр, например mana_max или melee_damage |
| value | Прибавка либо штраф |
| source | Источник: kind и label; дополнительно можно передать ID и контекст |
| attackId | null для общего бонуса данного вида; ID для бонуса конкретной атаки |
| condition | always либо unarmed |

Пример:

~~~php
$modifiers = [
    new StatModifier(
        target: 'melee_damage',
        value: 6,
        source: ['kind' => 'perk', 'id' => 15, 'label' => 'Перк «Пример»'],
    ),
    new StatModifier(
        target: 'melee_damage',
        value: 3,
        source: ['kind' => 'item', 'id' => 42, 'label' => 'Свойство меча'],
        attackId: 'sword-42',
    ),
];
~~~

Первый бонус действует на переданные ближние атаки. Второй — только на sword-42. Безоружное условие допускается только для ближнего урона и проверяется по явно переданному признаку unarmed.

Бонус к общему ресурсу нельзя привязать к атаке. Неизвестная цель, отсутствующий ID атаки и несовпадение её вида урона с целью бонуса отклоняются.

Описание не разбирается на числа. «+2 Малых урона ко всем атакам» означает прибавку 6 к каждому применимому виду урона; CharacterCalculationBuilder передаёт соответствующие модификаторы.

## Пример вызова

~~~php
$attributes = [
    'physiology' => ['name' => 'Физиология', 'level' => 9],
    'agility' => ['name' => 'Ловкость', 'level' => 3],
    'magic' => ['name' => 'Магия', 'level' => 4],
    'charisma' => ['name' => 'Харизма', 'level' => 3],
];
$attacks = [
    [
        'id' => 'sword-42',
        'mode' => 'melee',
        'damage_units' => 3,
        'source' => ['kind' => 'item', 'id' => 42, 'label' => 'Меч'],
    ],
];
$calculator = new CharacterCalculator(StatRules::defaults());
$result = $calculator->calculate($attributes, $modifiers, $attacks);
~~~

Имена классов в примере относятся к пространству Maxcuso\Roleplay\Rules.

Способы атак:

| mode | Базовый урон |
| --- | --- |
| melee | Физиология |
| ranged | Ловкость: дальнобойная атака или метательное оружие в ближнем бою |

| magic | Магия |

Один предмет может иметь разные варианты применения с отдельными ID. damage_units — добавка конкретного предмета/заклинания к базовому урону соответствующей атаки. Отсутствующее значение равно 0.

Для безоружной атаки передаётся mode = melee, unarmed = true и нулевой урон предмета.

## Результат

| Поле | Содержимое |
| --- | --- |
| stats | Общие параметры: мана, выносливость, грузоподъёмность, игнорируемый урон |
| base_damage | Вклад характеристик до бонусов и урона предмета |
| attacks | Каждый вариант атаки со своим итогом и слагаемыми |
| maximum_damage | Максимальная отдельная атака каждого вида урона |
| magic_circle | Доступный круг по текущей Магии |
| inventory_weight | Общий вес со слагаемыми по экземплярам |
| skill_check_bonuses | Текущий уровень навыка как общая прибавка к его проверке |

CalculatedValue содержит value и parts, сериализуется в JSON. Слагаемое хранит value и source. При снижении ниже нуля добавляется явное слагаемое «Минимум параметра»; итог равен 0.

Если доступные атаки не переданы, соответствующий maximum_damage равен null. Базовый вклад характеристики при этом остаётся в base_damage. Это различает отсутствие доступного варианта и нулевой урон. При равных максимумах выбран первый вариант в переданном списке.
В анкете отсутствие варианта не означает «Нет»: CharacterSheet показывает соответствующий base_damage.
При наличии атаки используется её готовый итог (база + оружие/заклинание + применимые эффекты),
без повторного сложения с базой. Бонус рукопашного перка задаётся обычным эффектом с условием unarmed,
а не названием или специальным кодом перка. При отсутствии оружия безоружный вариант включает этот эффект.

Вес считается как количество × вес экземпляра, отсутствие веса или null означает 0. Повтор одного экземпляра в списке отклоняется. Вес и грузоподъёмность поддерживают тысячные доли килограмма. Урон, ресурсы и бонусы проверки навыка — целые числа.

Новый калькулятор не выдаёт уже отформатированные строки урона. Существующая функция damage() в клиентском presentation.ts превращает числовой итог в ступени при показе. Правила форматирования не копируются в каждую формулу.

## Защита

В stats.ignored_damage уже включены Физиология и переданные прибавки, например от применимого щита. AttackCalculator::remainingDamage() уменьшает одну входящую атаку на этот итог:

~~~php
$remaining = $attackCalculator->remainingDamage(
    incoming: 27,
    defense: $result['stats']['ignored_damage'],
);
~~~

При Физиологии 22 и щите +Малый защита равна 18 + 3 = 21. Входящие 27 становятся 6. Каждая следующая атака уменьшается заново; значение защиты не расходуется. Остаток не может быть отрицательным.

## Что ещё не подключено

Эффекты и сбор доступных атак уже подключены: [10-effects.md](10-effects.md), [11-available-attacks.md](11-available-attacks.md). Следующие подсистемы:

- Боевая система действий и ходов.

Новая версия не установлена на рабочий форум. Никаких миграций или изменений рабочих персонажей этот этап не выполняет.

## Проверка

~~~text
docker compose run --rm --no-deps -T --entrypoint php forum packages/roleplay-new/tests/check-stat-calculator.php
~~~

Тест использует только PHP и данные в памяти. Проверяются граничные уровни, числовые бонусы, два оружия, метательное оружие в ближнем бою, безоружное условие, защита со щитом, отрицательный итог, вес стопок, источники слагаемых, сериализация и неизменность входных данных.

Пороги и обучение согласованы с [таблицами развития](05-development-rules.md). Для правки формул меняйте resources/rules/stats.php и обновляйте соответствующие сценарии. Изменение этого файла не требует миграции.
