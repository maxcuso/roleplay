# Подмодуль квестов и QuestEvents

**История интеграции.** С 28 октября 2026 года механизм событий перенесён внутрь
Roleplay, отдельный QuestEvents на локальной копии отключён. Актуальное устройство,
установка и проверки описаны в [Событиях внутри Roleplay](32-events-migration.md).
Ниже сохранено описание первоначальной интеграции от 12 октября.

Реализовано 12 октября 2026 года. Общий механизм событий находится в QuestEvents,
правила выбора персонажа — в Roleplay. Оба расширения обновляются вместе.

## Поведение

- При включённом Roleplay в редакторе события доступен тип «Квест» с прежними
  рангами, наградами и настройками запуска. Переключатель квестов в QuestEvents сохраняется.
- Для записи требуется свой активный персонаж и право просмотра Roleplay.
  Персонажи на проверке, погибшие и архивные не предлагаются.
- Один активный персонаж выбирается автоматически. При нескольких открывается
  компактное окно выбора; до подтверждения место не занимается.
- Без активного персонажа запись невозможна, в том числе через прямой API-запрос.
- Привязка сохраняется за конкретным участием. Переключение персонажа в профиле
  не меняет участника квеста. Имя персонажа видно в подсказке и списке участников.
- Выход, исключение и удаление события очищают дополнительные связи участия.
  При удалении персонажа сохраняется его последнее имя для истории.
- Форумные события продолжают принимать аккаунты без персонажей.

Количество мест, общий лимит двух незавершённых событий на аккаунт,
расписание, публикация темы, доступ по исходному посту и завершение не изменены.
Награды остаются отображаемыми параметрами: автоматическая выдача не добавлена.
У старых записей участников нет автоматически назначенного персонажа;
они сохраняются и продолжают отображаться как аккаунты.

## Код и данные

- `QuestEvents/Participation/ParticipationTypes` — общий реестр правил типов.
  Связь с Roleplay подключается его сервис-провайдером при включённом QuestEvents.
- `ParticipationType` — небольшой контракт: варианты регистрации, сохранение,
  удаление дополнительных данных и подписи участников.
- `Roleplay/Quests/QuestParticipation` — единственное место выбора персонажа,
  проверки владельца и статуса. Для новых правил квеста начинай с этого подмодуля.
- `EventRegistration` хранит участие в прежней таблице и вызывает дополнение
  внутри той же транзакции, до расчёта расписания и запуска.
- `roleplay_quest_participants` хранит только event_id/user_id → character_id
  и имя для истории. Второй базы событий и второго списка участников нет.
  Новая миграция принадлежит Roleplay и не требует таблиц QuestEvents при установке.
- Общий API возвращает `registrationOptions` и дополнительное поле `character`
  у участника. Имена и варианты читаются сервером, клиент не определяет права.
- `RegistrationChoiceModal` в QuestEvents — общий показ вариантов дополнения.
  `eventCardState` использует прежний POST /quest-events/{id}/participants,
  добавляя characterId только для регистрации с выбором персонажа.

При отключённом Roleplay новые квесты не создаются и новая запись в старый квест
недоступна. Старые карточки и редактирование существующих квестов сохраняются;
общий жизненный цикл события продолжает обслуживаться QuestEvents.

## Проверка и установка

После обновления обоих расширений: `php flarum migrate`, затем
`php flarum cache:clear`. В тестовой копии localhost:8081 это выполнено.
Новый JavaScript QuestEvents собран в js/dist.

Проверки ограничены критическими сценариями:
- `tests/check-quest-integration.php` — настоящая загрузка двух расширений,
  API, варианты 0/1/несколько персонажей, чужой/неактивный персонаж,
  откат неудачной записи, выход, исключение, удаление и обычное событие.
  Только установленная тестовая копия; изменения откатываются транзакцией.
- `tests/check-quest-client.cjs` — доступность типа, автоматический выбор,
  открытие окна без занятия места и отправка выбранного персонажа.

Лимиты по персонажам, модераторская и автоматическая выдача наград относятся
к будущей разработке; текущая интеграция их не меняет.
