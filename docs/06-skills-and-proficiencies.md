# Навыки и владения: архитектура и места настройки

Реализовано в Roleplay New, без подключения нового пакета к форуму. Нужные пороги перечислены в [правилах развития](05-development-rules.md).

## Что доступно

В админке добавлена группа «Навыки и владения» с двумя таблицами и редакторами. Расположение группы можно менять в реестре навигации; данные и операции от него не зависят. Общую перестройку меню обсудим позже.

Навык: название, описание, характеристика, статус, порядок и три привязки перков по ID. Описание, изображение и редкость перка меняются в «Перках». Переименование перка не нарушает привязку.

У нового навыка статус выключен. Его можно сохранить незаполненным; включение разрешено только после выбора перков для I, II и III. Выключенный перк может оставаться в привязке, но проверка обучения запрещает новую выдачу такого перка. Если персонаж уже имеет его, повышение навыка разрешено без повторной выдачи.

Владение: название, описание, характеристика, статус и порядок. У владения нет уровня, собственного урона или отдельной иконки.

Оба вида наследуют значок характеристики. Изменение её значка отражается в таблицах и редакторах. Локальные замены Pro-иконок работают через прежний общий механизм.

## Данные и API

Добавлены таблицы roleplay_skills, roleplay_skill_levels, roleplay_weapon_proficiencies. У навыка и владения есть внешний ключ на характеристику. У строки уровня — ссылка на навык и nullable-ссылка на перк.

Пара (skill_id, level) уникальна, уровень ограничен диапазоном 1–3. Удаление неиспользованного навыка удаляет его дочерние привязки. Удалить перк, связанный с уровнем, или характеристику с навыками/владениями нельзя: сервер возвращает конфликт. Запись можно выключить.

Схема добавлена в первую миграцию новой версии: она ещё не применена на форуме. В миграции нет иконок, названий или правил выдачи.

Оба каталога используют общий административный API: ключи skills и proficiencies. GET поддерживает поиск, статус, страницу и фильтр attribute с числовым ID. POST/PUT получают revision и fields; PATCH меняет статус. Доступ только администратору.

Пример полей навыка:

~~~json
{
  "name": "Рукопашный бой",
  "description": "Описание навыка",
  "attribute_id": 1,
  "enabled": true,
  "sort_order": 0,
  "levels": [
    {"level": 1, "perk_id": 11},
    {"level": 2, "perk_id": 12},
    {"level": 3, "perk_id": 13}
  ]
}
~~~

Числа в примере условные. Для незаполненного выключенного навыка perk_id может быть null. Список всегда возвращает три уровня; неизвестные поля и повторяющиеся уровни отклоняются.

Сохранение названия, статуса и всех привязок — одна транзакция общей версии справочников. Ошибка на последней дочерней строке восстанавливает предыдущую запись и версию. В таблице и селекторах уровни читаются одним запросом на набор навыков.

## Начальное наполнение

Явный SeedBaseCatalogs добавляет отсутствующие 4 характеристики, 11 навыков и 6 владений. Навыки создаются выключенными с пустыми привязками. Перки не создаются и не подбираются автоматически по названиям.

Повторный запуск сохраняет изменённые имена, иконки, статусы и привязки. Правка файла начальных данных не обновляет существующие строки.

После будущей установки администратор создаст или перенесёт определения перков, выберет три ссылки в каждом навыке и включит готовые навыки. Расовые привязки остаются в редакторе расы.

## Чистые проверки обучения

Rules получает готовые типизированные определения и доверенное состояние: уровень характеристики, текущий уровень навыка/наличие владения, остаток выборов именно этой характеристики, перки и список уже полученных ID.

Ответ содержит allowed, стабильный code, объяснение reason и детали следующего перехода. Для навыка: target_level, perk_id, grant_perk, already_owned_perk, consume_choice, check_bonus. Для владения: action и consume_choice.

earnedChoices() возвращает всё заработанное число выборов, **не доступный остаток**. Расходы и повторный запрос должны учитываться будущей операцией развития. Результат проверки сам не меняет персонажа.

Когда подключим выдачи, источник навыкового перка будет храниться у выдачи: источник «Навык», ID навыка и достигнутый уровень. Если перк уже есть, первоначальный источник сохраняется. Перки старых уровней не удаляются. Замена ссылки в админке влияет на будущие получения; прошлые выдачи не переписываются.

## Границы этапа

Хранение и чтение уровней навыков и изученных владений добавлены в [08-character-state.md](08-character-state.md). Стартовое обучение, выдачи перков, автоматическое владение и сохранение прав выбора подключены в [12-character-creation.md](12-character-creation.md). Пока нет операции дальнейшего развития и списания опыта. Нет новых страниц мастера: их проектирование ждёт макетов пользователя.

Для будущего сохранения нужна отдельная операция с проверкой прав, блокировкой состояния персонажа, повторной проверкой требований, защитой повторного запроса и общей транзакцией. Определения изученных навыков и владений уже защищены от удаления ссылками таблиц состояния.

## Проверки

Из корня проекта:

~~~text
docker compose exec -T forum php packages/roleplay-new/tests/check-learning-rules.php
docker compose exec -T forum php packages/roleplay-new/tests/check-base-catalogs.php
node packages/roleplay-new/tests/check-admin-client.cjs
~~~

Проверки правил не используют базу. Проверки API создают уникальные временные таблицы, выполняют создание, откат и повторную установку, затем удаляют только свои таблицы. Проверяются целостность ссылок, выключенные черновики, быстрые изменения двух селекторов до перерисовки и наследование иконки.

Клиентская проверка запускает собранный код с настоящим Mithril; её ограничения и подготовка карты ядра описаны в [документации админки](04-admin-catalogs.md). Визуальное отображение в браузере пользователем пока не проверено.

Привязки владений и автоматический сбор атак: [11-available-attacks.md](11-available-attacks.md).
